Core Components

React Native maps JavaScript components to native platform views. Unlike the web, there is no DOM — every component is a bridge to a native widget.

Reanimated 3

Reanimated 3 runs animations entirely on the UI thread using worklets — JavaScript functions marked with 'worklet' directive that execute on the JS worklet runtime, bypassing the bridge.

import Animated, {
  useSharedValue, useAnimatedStyle,
  withTiming, withSpring, withDecay,
  withSequence, withRepeat, withDelay,
  runOnJS, interpolate, Extrapolation,
  useAnimatedScrollHandler,
} from 'react-native-reanimated';

function BouncingButton() {
  const scale = useSharedValue(1);

  const animatedStyle = useAnimatedStyle(() => ({
    transform: [{ scale: scale.value }],
  }));

  const handlePress = () => {
    scale.value = withSequence(
      withTiming(0.9, { duration: 80 }),
      withSpring(1, { damping: 4, stiffness: 200 }),
    );
  };

  return (
    <Animated.View style={[styles.button, animatedStyle]}>
      <Pressable onPress={handlePress}>
        <Text>Press Me</Text>
      </Pressable>
    </Animated.View>
  );
}

Worklets & runOnJS

// Worklet — runs on UI thread
function clamp(value, min, max) {
  'worklet';
  return Math.min(Math.max(value, min), max);
}

// runOnJS — call JS function from worklet
const updateState = (val) => setCount(val);  // JS function

const animatedStyle = useAnimatedStyle(() => {
  const clamped = clamp(shared.value, 0, 100);
  runOnJS(updateState)(clamped);  // bridge back to JS
  return { opacity: clamped / 100 };
});

Scroll Animations

function ParallaxHeader() {
  const scrollY = useSharedValue(0);
  const scrollHandler = useAnimatedScrollHandler({
    onScroll: (event) => {
      'worklet';
      scrollY.value = event.contentOffset.y;
    },
  });

  const headerStyle = useAnimatedStyle(() => ({
    transform: [{ translateY: interpolate(scrollY.value, [0, 200], [0, -100], Extrapolation.CLAMP) }],
    opacity: interpolate(scrollY.value, [0, 150], [1, 0], Extrapolation.CLAMP),
  }));

  return (
    <>
      <Animated.View style={[styles.header, headerStyle]} />
      <Animated.ScrollView onScroll={scrollHandler} scrollEventThrottle={16}>
        {/* content */}
      </Animated.ScrollView>
    </>
  );
}

Gesture Handler

import { GestureDetector, Gesture, GestureHandlerRootView } from 'react-native-gesture-handler';
import Animated, { useSharedValue, useAnimatedStyle, withSpring } from 'react-native-reanimated';

function DraggableCard() {
  const offsetX = useSharedValue(0);
  const offsetY = useSharedValue(0);
  const startX = useSharedValue(0);
  const startY = useSharedValue(0);

  const panGesture = Gesture.Pan()
    .onStart(() => {
      'worklet';
      startX.value = offsetX.value;
      startY.value = offsetY.value;
    })
    .onUpdate((e) => {
      'worklet';
      offsetX.value = startX.value + e.translationX;
      offsetY.value = startY.value + e.translationY;
    })
    .onEnd(() => {
      'worklet';
      offsetX.value = withSpring(0);
      offsetY.value = withSpring(0);
    });

  const animStyle = useAnimatedStyle(() => ({
    transform: [{ translateX: offsetX.value }, { translateY: offsetY.value }],
  }));

  return (
    <GestureHandlerRootView style={{ flex: 1 }}>
      <GestureDetector gesture={panGesture}>
        <Animated.View style={[styles.card, animStyle]} />
      </GestureDetector>
    </GestureHandlerRootView>
  );
}

New Architecture

React Native's new architecture (default in 0.74) replaces the asynchronous bridge with three pillars: JSI, Fabric, and TurboModules.

JSI (JavaScript Interface)

JSI allows JavaScript to hold references to C++ host objects and call methods synchronously. This eliminates JSON serialization overhead and enables synchronous method calls between JS and native.

Fabric Renderer

Fabric is a C++ reimplementation of the UIManager. It allows concurrent rendering (aligning with React 18's Concurrent Mode), priority-based updates, and synchronous layout reads (eliminating the double-render for onLayout).

TurboModules

TurboModules are lazily loaded native modules. They are defined with a TypeScript/Flow spec, and Codegen generates C++ and Java/ObjC boilerplate automatically, ensuring type safety at the bridge boundary.

// TurboModule spec (NativeSampleModule.ts)
import type { TurboModule } from 'react-native';
import { TurboModuleRegistry } from 'react-native';

export interface Spec extends TurboModule {
  multiply(a: number, b: number): Promise<number>;
  getConstantsSync(): { API_KEY: string };
}

export default TurboModuleRegistry.getEnforcing<Spec>('SampleModule');

Interview Q&A

Q1: What is the difference between React Native's old Bridge and the new JSI? Easy

Old Bridge: All communication between JavaScript and native happened asynchronously over a serialized JSON message queue. JS could not directly call native methods — it would post a message and wait for a response. This caused latency and could not pass complex objects by reference.

JSI (JavaScript Interface): JSI allows the JS runtime to hold C++ host object references and call methods synchronously (or schedule them without serialization). No JSON marshaling — objects are shared by reference across the bridge boundary. This enables synchronous layout reads, faster animations, and the foundation for TurboModules and Fabric.

Q2: What is useNativeDriver and when must you use it? Easy

useNativeDriver: true tells the Animated API to run the animation on the native UI thread instead of the JS thread. This avoids the JS thread bottleneck and produces buttery-smooth 60 fps animations even when JS is busy.

Works with: transform, opacity

Does NOT work with: layout properties like width, height, backgroundColor, paddingTop

For layout animations, use Reanimated 3 which runs on a separate worklet thread and supports more properties natively.

Q3: What is the difference between ScrollView and FlatList? Easy

ScrollView renders all its children at once. Good for screens with a small, known number of elements (settings screens, forms). Bad for long lists — high memory usage and slow initial render.

FlatList is virtualized: it only renders items currently visible in the viewport (plus a configurable buffer). Items that scroll off-screen are unmounted (or recycled). Suitable for lists of 50+ items. Requires data, renderItem, and keyExtractor.

Q4: Explain the React Navigation stack lifecycle — when do screens mount/unmount? Intermediate

In a Stack Navigator, screens remain mounted until popped. Navigating to a new screen pushes it; the previous screen stays in memory. Screens are unmounted only when popped off the stack.

Use the focus/blur events or useFocusEffect hook to run side effects when a screen comes into/leaves focus without mounting/unmounting:

useFocusEffect(
  useCallback(() => {
    fetchData();
    return () => cleanup();
  }, [])
);

In a Tab Navigator, tabs remain mounted after first visit by default. Use unmountOnBlur: true in screen options to unmount on tab switch (saves memory but loses scroll position).

Q5: What are Reanimated worklets and why do they improve performance? Intermediate

Worklets are JavaScript functions annotated with the 'worklet' directive. Reanimated 3 compiles them to run on the UI thread (a separate JS runtime called the worklet runtime, powered by Hermes), not the main JS thread.

This means gesture callbacks, scroll handlers, and animation computations execute synchronously on the UI thread — no async bridge round-trips. The result is animations that stay smooth even when the JS thread is doing heavy computation.

To call back into JS from a worklet, use runOnJS(fn)(args). To call into the worklet runtime from JS, use runOnUI(fn)(args).

Q6: How would you implement a pull-to-refresh with custom animation? Intermediate 
import Animated, {
  useSharedValue, useAnimatedScrollHandler, useAnimatedStyle, interpolate
} from 'react-native-reanimated';

const PULL_THRESHOLD = 80;

function PullToRefresh({ onRefresh }) {
  const pullDistance = useSharedValue(0);
  const [refreshing, setRefreshing] = useState(false);

  const scrollHandler = useAnimatedScrollHandler({
    onScroll: (e) => {
      'worklet';
      if (e.contentOffset.y < 0) {
        pullDistance.value = Math.abs(e.contentOffset.y);
      }
    },
    onEndDrag: (e) => {
      'worklet';
      if (pullDistance.value > PULL_THRESHOLD) {
        runOnJS(triggerRefresh)();
      }
      pullDistance.value = withSpring(0);
    },
  });

  const indicatorStyle = useAnimatedStyle(() => ({
    transform: [{ rotate: `${interpolate(pullDistance.value, [0, PULL_THRESHOLD], [0, 360])}deg` }],
    opacity: interpolate(pullDistance.value, [0, PULL_THRESHOLD], [0, 1]),
  }));

  return (/* ... */);
}
Q7: What is Fabric and how does it differ from the old UIManager? Intermediate

Old UIManager: Written in Java/ObjC, communicated asynchronously with the JS thread. Shadow tree (layout calculations via Yoga) ran on a separate shadow thread. UI updates were batched and applied asynchronously — could cause frame drops.

Fabric: C++ implementation of the renderer, shared across platforms. Key advantages:

  • Synchronous layout reads from JS (no double render for onLayout)
  • Supports React 18 Concurrent Mode (priority-based updates, startTransition)
  • C++ shadow tree is directly accessible from JS via JSI — no async handoff
  • Enables View Flattening — fewer native views needed for common patterns
Q8: How do TurboModules differ from legacy Native Modules? Intermediate

Legacy Native Modules: All loaded eagerly at startup regardless of use. Communication via the async bridge. No type safety — parameters passed as dynamic JSON.

TurboModules:

  • Loaded lazily (on first use) — faster app startup
  • Communicate via JSI — synchronous capability
  • Defined via TypeScript/Flow spec + Codegen generates type-safe C++/Java/ObjC bindings
  • Codegen generates the glue code — no manual bridge marshaling
Q9: How does Metro bundler handle module resolution differently from webpack? Intermediate

Metro is React Native's bundler. Key differences from webpack:

  • Designed for hot module replacement on mobile (Fast Refresh)
  • Supports platform-specific extensions: .ios.js, .android.js, .native.js resolved automatically
  • Delta bundles — sends only changed modules over the wire during development
  • Symlink support (stable in 0.72+)
  • No code splitting by default (single bundle), though RAM bundles exist for large apps
  • Inline requires (lazy evaluation) enabled in production via Hermes
Q10: What is Fast Refresh and how does it differ from Hot Reload? Easy

Hot Reload (deprecated): Attempted to patch running app state — was fragile and often broke when class components were used or module-level state existed.

Fast Refresh (introduced in RN 0.61): Built on React's new hot reloading API. Rerenders only the component whose source changed, preserving React state where possible. If a file exports non-React items or has module-level side effects, it does a full reload. Works correctly with hooks.

Q11: How would you detect and fix a memory leak in a React Native app? Advanced

Common causes in RN:

  • Event listeners not removed in useEffect cleanup
  • Animated values or gesture handlers holding stale closures
  • Long-lived timers (setInterval) not cleared
  • Large images in FlatList without removeClippedSubviews

Detection:

  • Hermes CDP memory snapshot in Chrome DevTools (via Metro tunnel)
  • react-native-performance-monitor for runtime heap tracking
  • Android Studio Memory Profiler / Xcode Instruments Allocations

Pattern: Always return cleanup functions from useEffect:

useEffect(() => {
  const subscription = eventEmitter.addListener('event', handler);
  const id = setInterval(tick, 1000);
  return () => {
    subscription.remove();
    clearInterval(id);
  };
}, []);
Q12: What are RAM Bundles and why would you use them? Advanced

RAM (Random Access Module) bundles split the JS bundle into individual module files. At startup, only the bootstrap code is loaded into memory. Modules are loaded on-demand as they're require()d.

Use cases: Large apps with many screens/modules where loading all code at startup causes slow TTI.

Types:

  • Indexed RAM bundle (iOS) — single file with a lookup index
  • File RAM bundle (Android) — separate files per module

Hermes bytecode bundles largely obsolete this pattern since Hermes's lazy compilation achieves similar benefits. For Hermes + New Architecture, prefer Hermes bytecode.

Q13: Explain the Gesture Handler v1 vs v2 API changes Intermediate

v1 (old API): Used HOC wrappers like PanGestureHandler, TapGestureHandler as JSX components. Composed gestures with simultaneousHandlers/waitFor props — verbose and error-prone.

v2 (RNGH 2.0+): Declarative Gesture object API with method chaining. Composed with Gesture.Race(), Gesture.Simultaneous(), Gesture.Exclusive(). Passed to GestureDetector component. Much cleaner and integrates natively with Reanimated 3 worklets.

Q14: How does EAS Update handle rollbacks and channels? Advanced

EAS Update uses channels (e.g., production, staging, preview) and branches. An app build subscribes to a channel. Updates published to a branch are routed to channels via mappings.

Rollback: Republish a previous update to the branch, or use eas update:republish to point the channel at an earlier update. The next app foreground will receive the old update.

Runtime version compatibility: Each update must match the build's runtimeVersion. If native code changed (new TurboModule, new Expo SDK), increment runtimeVersion — OTA updates won't be applied to incompatible binaries.

Q15: What is InteractionManager and when should you use it? Intermediate

InteractionManager.runAfterInteractions(callback) queues work to run after all running animations and interactions complete. This prevents expensive JS work from competing with navigation transitions or gesture animations.

Use for: Data fetching on screen mount after navigation, expensive list rendering, analytics events triggered on screen entry.

Note: In Reanimated 3 with the new architecture, worklets run on the UI thread so this pattern is less critical for animation-competing work — but it remains useful for scheduling expensive JS computation after screen transitions.

Q16: How does the New Architecture handle concurrent rendering? Advanced

Fabric aligns with React 18's Concurrent Mode. Key behaviours:

  • React can interrupt and restart render phases — renders are no longer synchronous "all or nothing"
  • High-priority updates (user input) can preempt lower-priority updates (data loading)
  • React's startTransition works: UI remains responsive during heavy state updates
  • Suspense boundaries work natively with Fabric's async layout
  • Fabric's C++ shadow tree supports concurrent tree diffing

In practice: use startTransition around non-urgent state updates (filtering a list, loading more data) to keep animations and inputs responsive.

Q17: What is the difference between expo-modules-core and the old react-native NativeModule pattern? Advanced

expo-modules-core provides a modern Swift/Kotlin-first API for writing native modules with minimal boilerplate, using the new architecture's Codegen-style approach via Expo's own code generation.

Key advantages: type safety enforced via Swift/Kotlin generics, automatic conversion between JS and native types, no manual RCT_EXPORT_METHOD or @ReactMethod annotations, hooks for module lifecycle (OnCreate, OnDestroy), and View props defined as Kotlin/Swift properties.

// Swift — Expo Module
public class SampleModule: Module {
  public func definition() -> ModuleDefinition {
    Name("Sample")
    AsyncFunction("multiply") { (a: Double, b: Double) -> Double in
      return a * b
    }
  }
}
Q18: Explain how getItemLayout improves FlatList performance Intermediate

Without getItemLayout, FlatList must render and measure each item before it can calculate scroll positions. This means jumping to an index (scrollToIndex) requires rendering all items up to that index first — O(n) rendering.

With getItemLayout, the list pre-computes layout for any index in O(1):

getItemLayout={(data, index) => ({
  length: ITEM_HEIGHT,       // fixed height of each item
  offset: ITEM_HEIGHT * index + SEPARATOR_HEIGHT * index,
  index,
})}

This enables fast scrollToIndex, reduces blank frames during fast scrolling, and avoids initial measurement renders.

Q20: What is the Yoga layout engine and what changed in Yoga 3.0? Advanced

Yoga is the cross-platform C++ layout engine that implements the Flexbox spec for React Native (and Litho, ComponentKit). It runs on the shadow thread computing layout before Fabric commits to the UI thread.

Yoga 3.0 (RN 0.74):

  • Corrects the gap property to accept percentage values
  • Implements align-content: space-evenly
  • Fixes absolute positioning interactions with padding
  • Closer conformance to the CSS Flexbox specification
  • Breaking: some edge case layout behaviours changed — test layout-heavy screens after upgrading
Q21: How does Hermes handle source maps for debugging production crashes? Very Advanced

Hermes bytecode bundles are compiled from JS at build time. Stack traces from production crashes reference bytecode offsets, not JS line numbers. To symbolicate:

  1. Build generates index.android.bundle.map (source map)
  2. Upload the source map to your crash reporter (Sentry, Bugsnag) alongside the binary
  3. The reporter uses the source map to map bytecode offset → original TS/JS line
# Manual symbolication with metro-symbolicate
npx metro-symbolicate index.android.bundle.map < crashlog.txt

EAS Build automatically generates and can optionally upload source maps to Sentry via sentry-expo.

Q22: Explain View Flattening in the New Architecture Very Advanced

View Flattening is an optimisation in Fabric where unnecessary native view nodes are eliminated. In the old architecture, every React component with a style or layout prop created a corresponding native view node. Complex component hierarchies created deep native view trees — expensive to traverse and render.

Fabric analyses the C++ shadow tree and merges view nodes that only provide layout props (no visual effect like background, border, overflow:hidden) into their parent. This reduces the number of native views created, lowering memory and rendering cost.

Developers can opt out with collapsable={false} (needed when you need a ref to the native view for measurement or animation).
