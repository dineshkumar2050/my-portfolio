Redux — Comprehensive Learning Reference

1. Overview

Redux is a predictable state container for JavaScript applications. It helps manage application state in a consistent, testable, and debuggable way by centralizing state in a single store.

Why Redux? The Problems It Solves

  • Prop drilling: Instead of passing state through many component layers, any component can read directly from the store
  • Shared mutable state bugs: One store, immutable updates — state changes are always traceable
  • Complex async flows: Middleware (thunk, saga) handles side effects outside components
  • Time-travel debugging: Because state is never mutated, you can replay/undo any action
  • Testability: Pure reducers are simple to unit test

Flux Architecture

Redux is inspired by Facebook's Flux architecture — a unidirectional data flow pattern.

flowchart LR A[User Action] --> B[Action Creator] B --> C[Action Object] C --> D[Dispatch] D --> E[Middleware] E --> F[Reducer] F --> G[New State in Store] G --> H[React Components Re-render] H --> A

Three Core Principles

  1. Single Source of Truth: The entire application state lives in one JavaScript object inside one store
  2. State is Read-Only: The only way to change state is to dispatch an action — an object describing what happened
  3. Changes Made with Pure Functions: Reducers are pure functions: (state, action) => newState. Same input always produces same output, no side effects

2. Version History

Redux 3.x — Classic Redux

  • redux-thunk: Most popular middleware for async actions — dispatches functions instead of plain objects
  • compose: Utility to compose multiple store enhancers / middleware
  • combineReducers: Split root reducer into smaller functions managing independent slices
  • Pattern: manual action types, action creators, reducers — very verbose

Redux 4.x — TypeScript & Hooks

  • Improved TypeScript definitions throughout
  • React-Redux hooks API: useSelector, useDispatch, useStore — replaced connect() HOC
  • Performance improvements: batched subscriber notifications
  • Subscription stability improvements for concurrent mode

Redux Toolkit 1.x — Modern Redux (2019+)

The official, opinionated toolset for Redux development. Eliminates boilerplate, includes best practices by default.

  • configureStore: Sets up store with redux-thunk middleware + DevTools out of the box
  • createSlice: Generates action creators + reducer from one object using Immer for immutable updates
  • createAsyncThunk: Generates thunks with pending/fulfilled/rejected lifecycle actions
  • createEntityAdapter: Normalized state management for collections of entities
  • createSelector (via Reselect): Memoized selectors
  • RTK Query (1.6+): Powerful data fetching and caching tool

Redux Toolkit 1.9 — Listener Middleware Stable

  • listenerMiddleware: Stable GA — react to dispatched actions and state changes with side effect listeners
  • Alternative to Redux Saga for many use cases — less complex, no generators

Redux Toolkit 2.0 (2024)

  • ESM/CJS dual publishing: Better tree-shaking, module compatibility
  • createDynamicMiddleware: Add middleware at runtime (micro-frontend support)
  • combineSlices: Lazy-load slice reducers for code splitting
  • Standalone selectors: slice.selectors with automatic input selector injection
  • Dropped support for IE11
  • Immer 10 (smaller, faster)

Reducers

// Reducer: pure function (currentState, action) => newState
// Rules: no mutations, no side effects, no Math.random(), no Date.now()

const initialState = {
  todos: [],
  filter: 'all',
  loading: false,
  error: null,
};

function todosReducer(state = initialState, action) {
  switch (action.type) {
    case 'todos/addTodo':
      return {
        ...state,
        todos: [...state.todos, action.payload]
      };

    case 'todos/toggleTodo':
      return {
        ...state,
        todos: state.todos.map(todo =>
          todo.id === action.payload
            ? { ...todo, done: !todo.done }
            : todo
        )
      };

    case 'todos/deleteTodo':
      return {
        ...state,
        todos: state.todos.filter(todo => todo.id !== action.payload)
      };

    case 'todos/setFilter':
      return { ...state, filter: action.payload };

    case 'todos/fetchPending':
      return { ...state, loading: true, error: null };

    case 'todos/fetchFulfilled':
      return { ...state, loading: false, todos: action.payload };

    case 'todos/fetchRejected':
      return { ...state, loading: false, error: action.payload };

    default:
      return state;  // IMPORTANT: always return current state for unknown actions
  }
}

Middleware

// Middleware signature: store => next => action => result
// Sits between dispatch and reducer — can inspect, modify, delay, or replace actions

// Redux Thunk: dispatches functions (for async)
const thunkMiddleware = store => next => action => {
  if (typeof action === 'function') {
    return action(store.dispatch, store.getState);
  }
  return next(action);
};

// Async action creator with thunk
function fetchTodos() {
  return async (dispatch, getState) => {
    dispatch({ type: 'todos/fetchPending' });
    try {
      const response = await fetch('/api/todos');
      const todos = await response.json();
      dispatch({ type: 'todos/fetchFulfilled', payload: todos });
    } catch (error) {
      dispatch({ type: 'todos/fetchRejected', payload: error.message });
    }
  };
}

// Custom logger middleware
const logger = store => next => action => {
  console.group(action.type);
  console.log('dispatching', action);
  console.log('prev state', store.getState());
  const result = next(action);
  console.log('next state', store.getState());
  console.groupEnd();
  return result;
};

// logger runs first, then thunk handles async, then reducer

useSelector

import { useSelector } from 'react-redux';

// Subscribe to a slice of state
function TodoList() {
  // Selector runs on every dispatch; re-renders only if result changes (===)
  const todos = useSelector(state => state.todos.todos);
  const filter = useSelector(state => state.todos.filter);

  const filteredTodos = useMemo(() => {
    if (filter === 'active') return todos.filter(t => !t.done);
    if (filter === 'done') return todos.filter(t => t.done);
    return todos;
  }, [todos, filter]);

  return (
    <ul>
      {filteredTodos.map(todo => <TodoItem key={todo.id} todo={todo} />)}
    </ul>
  );
}

// Equality function — prevent re-render when using object selectors
import { shallowEqual } from 'react-redux';

function UserInfo() {
  // Without shallowEqual: new object every call = re-render every dispatch
  const { name, email } = useSelector(
    state => ({ name: state.user.name, email: state.user.email }),
    shallowEqual
  );
  return <div>{name} ({email})</div>;
}

// Better: use separate selectors OR memoized selector (createSelector)
function UserInfo() {
  const name = useSelector(state => state.user.name);
  const email = useSelector(state => state.user.email);
  return <div>{name} ({email})</div>;
}

createSlice

import { createSlice, PayloadAction } from '@reduxjs/toolkit';

// createSlice generates action creators AND reducer from one definition
// Uses Immer internally — you CAN mutate draft state directly!

interface Todo {
  id: string;
  text: string;
  done: boolean;
  priority: 'low' | 'medium' | 'high';
}

interface TodosState {
  items: Todo[];
  filter: 'all' | 'active' | 'done';
  loading: boolean;
  error: string | null;
}

const todosSlice = createSlice({
  name: 'todos',        // prefix for generated action types: 'todos/addTodo'
  initialState: {
    items: [],
    filter: 'all',
    loading: false,
    error: null,
  } as TodosState,

  reducers: {
    // Direct mutation with Immer — no spread needed!
    addTodo(state, action: PayloadAction<{ text: string; priority: Todo['priority'] }>) {
      state.items.push({
        id: crypto.randomUUID(),
        text: action.payload.text,
        priority: action.payload.priority,
        done: false,
      });
    },

    toggleTodo(state, action: PayloadAction<string>) {
      const todo = state.items.find(t => t.id === action.payload);
      if (todo) todo.done = !todo.done;  // direct mutation — Immer handles it!
    },

    deleteTodo(state, action: PayloadAction<string>) {
      state.items = state.items.filter(t => t.id !== action.payload);
    },

    setFilter(state, action: PayloadAction<TodosState['filter']>) {
      state.filter = action.payload;
    },

    // prepare callback: transform input before storing
    addTodoWithTimestamp: {
      reducer(state, action: PayloadAction<Todo>) {
        state.items.push(action.payload);
      },
      prepare(text: string, priority: Todo['priority'] = 'medium') {
        return {
          payload: {
            id: crypto.randomUUID(),
            text,
            priority,
            done: false,
            createdAt: new Date().toISOString(),  // add metadata in prepare
          }
        };
      }
    },
  },

  // extraReducers: handle actions from OTHER slices or createAsyncThunk
  extraReducers: (builder) => {
    builder
      .addCase(fetchTodos.pending, (state) => {
        state.loading = true;
        state.error = null;
      })
      .addCase(fetchTodos.fulfilled, (state, action) => {
        state.loading = false;
        state.items = action.payload;
      })
      .addCase(fetchTodos.rejected, (state, action) => {
        state.loading = false;
        state.error = action.payload as string;
      })
      // Handle actions from other slices
      .addCase(userLoggedOut, (state) => {
        state.items = [];  // clear todos on logout
      });
  },
});

// Export auto-generated action creators
export const { addTodo, toggleTodo, deleteTodo, setFilter } = todosSlice.actions;

// Export reducer
export default todosSlice.reducer;

// Selectors — can be defined here or in a separate selectors file
export const selectAllTodos = (state: RootState) => state.todos.items;
export const selectFilter = (state: RootState) => state.todos.filter;
export const selectLoading = (state: RootState) => state.todos.loading;

createAsyncThunk

import { createAsyncThunk } from '@reduxjs/toolkit';

// createAsyncThunk(typePrefix, payloadCreator)
// Generates 3 action types: typePrefix/pending, typePrefix/fulfilled, typePrefix/rejected

export const fetchTodos = createAsyncThunk(
  'todos/fetchTodos',   // action type prefix
  async (userId: string, thunkAPI) => {
    // thunkAPI provides: dispatch, getState, extra, requestId, signal, abort, rejectWithValue

    // getState — access other slices
    const token = (thunkAPI.getState() as RootState).auth.token;

    // signal — AbortController signal (for fetch cancellation)
    const response = await fetch(`/api/users/${userId}/todos`, {
      headers: { Authorization: `Bearer ${token}` },
      signal: thunkAPI.signal,  // cancel fetch when thunk is aborted
    });

    if (!response.ok) {
      // rejectWithValue — send structured error to rejected case
      return thunkAPI.rejectWithValue({
        status: response.status,
        message: await response.text(),
      });
    }

    return response.json();  // return value becomes action.payload in fulfilled
  },
  {
    // condition: skip dispatch if condition returns false
    condition: (userId, { getState }) => {
      const { todos } = getState() as RootState;
      if (todos.loading) return false;  // already loading — don't dispatch again
    },

    // dispatchConditionRejection: dispatch rejected action if condition is false
    dispatchConditionRejection: false,
  }
);

// Handling results in component
function TodoLoader({ userId }) {
  const dispatch = useAppDispatch();
  const loading = useAppSelector(state => state.todos.loading);

  useEffect(() => {
    const promise = dispatch(fetchTodos(userId));
    // Can abort the thunk
    return () => promise.abort();
  }, [userId, dispatch]);

  return loading ? <Spinner /> : <TodoList />;
}

// Unwrapping the result
async function handleSaveTodo(text) {
  try {
    // unwrapResult or .unwrap() throws on rejection
    const savedTodo = await dispatch(saveTodo({ text })).unwrap();
    console.log('Saved:', savedTodo);
  } catch (rejectedValue) {
    console.error('Failed:', rejectedValue);
  }
}

// Multiple sequential thunks
export const refreshData = createAsyncThunk('app/refresh', async (_, thunkAPI) => {
  await thunkAPI.dispatch(fetchTodos());
  await thunkAPI.dispatch(fetchNotifications());

import { createEntityAdapter, createSlice } from '@reduxjs/toolkit';

// EntityAdapter: manages normalized state for collections
// Provides CRUD operations and selectors automatically

interface User {
  id: string;
  name: string;
  email: string;
  role: 'admin' | 'user';
}

// Create adapter — can specify custom sortComparer
const usersAdapter = createEntityAdapter<User>({
  // Optional: keep entities sorted
  sortComparer: (a, b) => a.name.localeCompare(b.name),
});

// Adapter creates initial state: { ids: [], entities: {} }
// ids: sorted array of IDs
// entities: dictionary { [id]: entity }

const usersSlice = createSlice({
  name: 'users',
  initialState: usersAdapter.getInitialState({
    loading: false,   // extra state fields alongside entities
    error: null as string | null,
  }),

  reducers: {
    // CRUD operations from adapter
    userAdded: usersAdapter.addOne,          // add single entity
    usersAdded: usersAdapter.addMany,         // add array of entities
    userUpdated: usersAdapter.updateOne,      // { id, changes: Partial<User> }
    userUpserted: usersAdapter.upsertOne,     // add or update
    userRemoved: usersAdapter.removeOne,      // remove by ID
    usersRemoved: usersAdapter.removeMany,    // remove array of IDs
    usersReceived: usersAdapter.setAll,       // replace all entities

    userRoleChanged(state, action: PayloadAction<{ id: string; role: User['role'] }>) {
      // Can combine adapter methods with custom logic
      usersAdapter.updateOne(state, {
        id: action.payload.id,
        changes: { role: action.payload.role },
      });
    },
  },

  extraReducers: (builder) => {
    builder
      .addCase(fetchUsers.fulfilled, (state, action) => {
        state.loading = false;

      });

});

6. RTK Query

RTK Query is a powerful data fetching and caching tool built into Redux Toolkit. It eliminates the need to write thunks, reducers, or selectors for server state.

import { createApi, fetchBaseQuery } from '@reduxjs/toolkit/query/react';

// Define your API
export const todosApi = createApi({
  reducerPath: 'todosApi',          // key in Redux store
  baseQuery: fetchBaseQuery({
    baseUrl: '/api',
    prepareHeaders: (headers, { getState }) => {
      const token = (getState() as RootState).auth.token;
      if (token) headers.set('Authorization', `Bearer ${token}`);
      return headers;
    },
  }),

  // Tag types for cache invalidation
  tagTypes: ['Todo', 'User'],

  endpoints: (builder) => ({
    // QUERY: GET request — cached
    getTodos: builder.query<Todo[], { userId: string; filter?: string }>({
      query: ({ userId, filter }) => ({
        url: `/users/${userId}/todos`,
        params: filter ? { filter } : undefined,
      }),
      providesTags: (result) =>
        result
          ? [
              ...result.map(({ id }) => ({ type: 'Todo' as const, id })),
              { type: 'Todo', id: 'LIST' },
            ]
          : [{ type: 'Todo', id: 'LIST' }],
      // Transform response
      transformResponse: (response: ApiTodo[]) =>
        response.map(t => ({ ...t, createdAt: new Date(t.createdAt) })),
    }),

    getTodoById: builder.query<Todo, string>({
      query: (id) => `/todos/${id}`,
      providesTags: (result, error, id) => [{ type: 'Todo', id }],
    }),

    // MUTATION: POST/PUT/DELETE — triggers cache invalidation
    addTodo: builder.mutation<Todo, Partial<Todo>>({
      query: (body) => ({ url: '/todos', method: 'POST', body }),
      // Invalidate LIST cache — triggers refetch of getTodos
      invalidatesTags: [{ type: 'Todo', id: 'LIST' }],
    }),

    updateTodo: builder.mutation<Todo, { id: string; changes: Partial<Todo> }>({
      query: ({ id, changes }) => ({
        url: `/todos/${id}`,
        method: 'PATCH',
        body: changes,
      }),
      // Invalidate specific todo
      invalidatesTags: (result, error, { id }) => [{ type: 'Todo', id }],

      // OPTIMISTIC UPDATES
      async onQueryStarted({ id, changes }, { dispatch, queryFulfilled }) {
        // Update cache optimistically before server responds
        const patchResult = dispatch(
          todosApi.util.updateQueryData('getTodos', { userId: 'me' }, (draft) => {
            const todo = draft.find(t => t.id === id);
            if (todo) Object.assign(todo, changes);
          })
        );
        try {
          await queryFulfilled;  // if server succeeds, keep optimistic update
        } catch {
          patchResult.undo();    // if server fails, rollback
        }
      },
    }),

    deleteTodo: builder.mutation<void, string>({
      query: (id) => ({ url: `/todos/${id}`, method: 'DELETE' }),
      invalidatesTags: (result, error, id) => [{ type: 'Todo', id }],
    }),
  }),
});

// Auto-generated hooks

// Basic saga
function* fetchUserSaga(action) {
  try {
    // call: invoke async function and wait (blocking)
    const token = yield select(state => state.auth.token);
    const user = yield call(fetchUserApi, action.payload, token);
    yield put(setUser(user));         // dispatch action on success
  } catch (error) {
    yield put(setError(error.message));  // dispatch action on error
  }
}

// Watcher saga — listens for actions
function* watchFetchUser() {
  // takeLatest: if FETCH_USER dispatched while previous saga running,
  // cancel the previous one and start fresh (good for search/filter)
  yield takeLatest('FETCH_USER', fetchUserSaga);
}

// Complex: race condition — fetch with timeout
function* fetchWithTimeout(url) {
  const { data, timeout } = yield race({
    data: call(fetch, url).then(r => r.json()),
    timeout: delay(5000),
  });

  if (timeout) throw new Error('Request timed out');
  return data;
}

// Complex: cancellable fetch
function* cancellableFetch(url) {
  try {
    const data = yield call(fetchWithTimeout, url);
    yield put(dataReceived(data));
  } finally {
    // `cancelled()` is true if saga was cancelled by parent
    if (yield cancelled()) {
      yield put(fetchCancelled());
    }
  }
}

function* watchWithCancel() {
  while (true) {
    yield take('FETCH_START');
    const fetchTask = yield fork(cancellableFetch, '/api/data');
    yield take('FETCH_CANCEL');  // wait for cancel action
    yield cancel(fetchTask);     // cancel the fetch
  }
}

// Complex: parallel operations
function* loadDashboard() {
  const [user, posts, notifications] = yield all([
    call(fetchUser),
    call(fetchPosts),
    call(fetchNotifications),
  ]);

// Error handling with channels
function* webSocketSaga() {
  const channel = yield call(createWebSocketChannel, 'wss://api.example.com');

    while (true) {
      const message = yield take(channel);
      yield put(messageReceived(message));
    }
  } finally {
    channel.close();
  }
}

  yield all([
    watchFetchUser(),
    watchWithCancel(),
    webSocketSaga(),

}

Q1. What is Redux and what problem does it solve?

Redux is a predictable state container for JavaScript applications. It centralizes application state in a single store and provides strict rules for how that state can change.

Problems Redux solves:

  • Prop drilling: Any component can access state from the store directly

Q2. What are the three principles of Redux?
  1. Single source of truth: The state of your entire application is stored in a single object tree within a single store. This makes it easy to reason about state and implement features like undo/redo.
  2. State is read-only: The only way to change state is to dispatch an action — a plain object describing what happened. This ensures no code can write to state directly, making changes predictable and centralizable.
  3. Changes are made with pure functions: Reducers are pure functions that take the previous state and an action, and return the next state. Pure = same inputs always produce same outputs, no side effects.

    default: return state;  // same input = same output, no side effects

Q4. What is a reducer and what rules must it follow?

A reducer is a pure function that calculates the next state based on the current state and an action: (state, action) => newState.

Rules reducers must follow:

  • Must NOT mutate the existing state — always return a new object/array
  • Must NOT produce side effects (no API calls, no timers, no console.log in production)
  • Must NOT use non-deterministic values (no Math.random(), no Date.now(), no crypto.randomUUID())
  • Must always return the current state for unknown action types
  • Must handle undefined state (provide default via default parameter)
// WRONG reducer — breaks the rules

    console.log(state);     // SIDE EFFECT!
    return state;

}

      });

Q4. How do you handle optimistic updates with RTK Query?

Optimistic updates: update the UI immediately before the server responds, then revert if the server fails.

// RTK Query optimistic update pattern using onQueryStarted
const postsApi = createApi({
  baseQuery: fetchBaseQuery({ baseUrl: '/api' }),
  tagTypes: ['Post'],
  endpoints: (builder) => ({
    getPosts: builder.query({
      query: () => '/posts',
      providesTags: ['Post'],
    }),

    toggleLike: builder.mutation({
      query: ({ postId, liked }) => ({
        url: `/posts/${postId}/like`,
        method: 'PATCH',
        body: { liked },
      }),

      async onQueryStarted({ postId, liked }, { dispatch, queryFulfilled }) {
        // 1. OPTIMISTICALLY update the cache before server responds
        const patchResult = dispatch(
          postsApi.util.updateQueryData('getPosts', undefined, (draft) => {
            const post = draft.find(p => p.id === postId);
            if (post) {
              post.liked = liked;
              post.likeCount += liked ? 1 : -1;
            }
          })
        );

        try {
          // 2. Wait for server response
          const { data: serverPost } = await queryFulfilled;
          // Optionally sync with server's authoritative data
          dispatch(
            postsApi.util.updateQueryData('getPosts', undefined, (draft) => {
              const post = draft.find(p => p.id === postId);
              if (post) Object.assign(post, serverPost);
            })
          );
        } catch {
          // 3. REVERT the optimistic update on failure
          patchResult.undo();
          // Show error notification
          dispatch(showNotification({ type: 'error', message: 'Failed to update like' }));
        }
      },
    }),
  }),
});

Q1. Explain RTK Query's caching mechanism with tags. How do you design cache invalidation?

RTK Query uses a tag-based cache invalidation system. Queries declare what tags they "provide"; mutations declare what tags they "invalidate". When a mutation runs, RTK Query automatically refetches all queries whose tags were invalidated.

const api = createApi({
  tagTypes: ['Post', 'User', 'Comment'],
  endpoints: (builder) => ({
    // Tags are like "cache labels"

    // LIST endpoint — provides a general list tag
    getPosts: builder.query({
      query: () => '/posts',
      providesTags: (result) =>
        result
          ? [
              // Tag each individual post
              ...result.map(({ id }) => ({ type: 'Post', id })),
              // Tag the whole list
              { type: 'Post', id: 'LIST' },
            ]
          : [{ type: 'Post', id: 'LIST' }],
    }),

    // GET ONE endpoint — provides specific entity tag
    getPost: builder.query({
      query: (id) => `/posts/${id}`,
      providesTags: (result, error, id) => [{ type: 'Post', id }],
    }),

    // CREATE — invalidates the list (forces refetch of getPosts)
    createPost: builder.mutation({
      query: (body) => ({ url: '/posts', method: 'POST', body }),
      invalidatesTags: [{ type: 'Post', id: 'LIST' }],
    }),

    // UPDATE — invalidates both the specific post AND the list
    updatePost: builder.mutation({
      query: ({ id, ...body }) => ({ url: `/posts/${id}`, method: 'PATCH', body }),
      invalidatesTags: (result, error, { id }) => [
        { type: 'Post', id },          // refetch getPost(id)
        { type: 'Post', id: 'LIST' },  // refetch getPosts
      ],
    }),

    // DELETE — invalidate specific entry from list
    deletePost: builder.mutation({
      query: (id) => ({ url: `/posts/${id}`, method: 'DELETE' }),
      invalidatesTags: (result, error, id) => [
        { type: 'Post', id },
        { type: 'Post', id: 'LIST' },
      ],
    }),

    // Cross-entity invalidation
    addComment: builder.mutation({
      query: ({ postId, text }) => ({ url: `/posts/${postId}/comments`, method: 'POST', body: { text } }),
      // Invalidate the post (comment count changes) and comments
      invalidatesTags: (result, error, { postId }) => [
        { type: 'Post', id: postId },
        { type: 'Comment', id: 'LIST' },
      ],
    }),
  }),

Q2. How does Redux Saga handle complex async flows? Demonstrate takeLatest and race. 
import { takeLatest, take, race, call, put, delay, cancelled, fork, cancel, select } from 'redux-saga/effects';

// SCENARIO: Search-as-you-type with debounce and cancellation

function* searchSaga(action) {
  try {
    // Debounce: wait 300ms before making API call
    // If another SEARCH action arrives during wait, takeLatest cancels this saga
    yield delay(300);

    const token = yield select(state => state.auth.token);
    const results = yield call(searchAPI, action.payload.query, token);
    yield put(searchSuccess(results));
  } catch (error) {
    if (!(yield cancelled())) {
      yield put(searchFailure(error.message));
    }
  } finally {
    if (yield cancelled()) {
      // Saga was cancelled (new search started) — clean up if needed
      yield put(searchCancelled());
    }
  }
}

function* watchSearch() {
  // takeLatest: cancels previous searchSaga if new SEARCH dispatched

function* loginFlowSaga() {
  while (true) {
    // Wait for login request
    const { payload } = yield take('auth/loginRequested');

    // Fork login task (non-blocking)
    const loginTask = yield fork(performLoginSaga, payload);

    // Wait for logout OR login to complete
    const { logout } = yield race({
      logout: take('auth/logoutRequested'),
      loginSuccess: take('auth/loginSuccess'),
    });

      yield cancel(loginTask);  // cancel login if user logged out during it
      yield call(performLogoutSaga);
    }
  }
}

  try {
    // Load critical data in parallel
    const [user, config] = yield all([
      call(fetchUser),
      call(fetchConfig),
    ]);

Q2. How does Redux Toolkit's Immer integration work? What are the edge cases and limitations?

RTK uses Immer inside createSlice and createReducer. Immer wraps state in a Proxy that tracks mutations and produces a new immutable state tree from them.

import produce from 'immer';

// How Immer works internally:
function createSliceReducer(recipe) {
  return function reducer(state = initialState, action) {
    return produce(state, (draft) => {
      recipe(draft, action);  // recipe mutates draft
      // Immer Proxy intercepts mutations and records them
      // After recipe returns, Immer produces new immutable state
      // Structural sharing: unchanged parts share references with old state
    });
  };
}

// EDGE CASES AND LIMITATIONS:

// 1. Cannot mix mutation AND returning new state
const badReducer = createReducer(initialState, (builder) => {
  builder.addCase(setUser, (state, action) => {
    state.user = action.payload;  // mutation
    return { ...state, extra: true };  // ALSO returning! — Immer throws error
  });
});
// RULE: either mutate the draft OR return a new value, never both

// 2. Must not escape the draft (don't store draft reference outside produce)
let escapedDraft;
const reducer = createReducer(initial, (builder) => {
  builder.addCase(someAction, (state) => {
    escapedDraft = state;  // BAD: storing draft ref
    state.x = 1;
  });
});
// After produce completes, draft is frozen — escapedDraft.x throws

// 3. Cannot produce non-plain-object values from recipe
// If you return undefined from recipe, Immer uses the mutated draft
// If you return something else, Immer uses that as the new state
builder.addCase(resetState, () => {
  return initialState;  // CORRECT: return entirely new state
  // DON'T: state = initialState  // reassigning doesn't work (it's a proxy)
});

// Real-time collaborative editing requires:
// - Optimistic local updates (feel instant)
// - Operational transformation / CRDT for conflict resolution
// - WebSocket for real-time sync
// - Pending operations queue

// State shape
const initialState = {
  document: {
    id: null,
    content: '',         // authoritative content
    version: 0,          // server version
  },
  pendingOps: [],        // local ops not yet confirmed by server
  collaborators: {},     // other users' cursor positions
  syncStatus: 'connected', // 'connected' | 'reconnecting' | 'offline'
};

// Slice
const documentSlice = createSlice({
  name: 'document',
  initialState,
  reducers: {
    // LOCAL: user types — apply immediately, add to pending queue
    localInsert(state, action) {
      const { position, text, opId } = action.payload;
      // Apply to local content immediately (optimistic)
      state.document.content =
        state.document.content.slice(0, position) + text +
        state.document.content.slice(position);
      // Queue for server sync
      state.pendingOps.push({ type: 'insert', position, text, opId, version: state.document.version });
    },

    // SERVER ACK: operation confirmed, remove from pending
    serverAck(state, action) {
      const { opId, newVersion } = action.payload;
      state.pendingOps = state.pendingOps.filter(op => op.opId !== opId);
      state.document.version = newVersion;
    },

    // SERVER BROADCAST: another user made a change
    remoteOperation(state, action) {
      const { op, version } = action.payload;
      // Transform op against pending ops (Operational Transformation)
      let transformedOp = op;
      for (const pending of state.pendingOps) {
        transformedOp = transformOperation(transformedOp, pending);
      }
      // Apply transformed op
      applyOp(state.document, transformedOp);
      state.document.version = version;
      // Rebase pending ops against new server state
      state.pendingOps = rebasePendingOps(state.pendingOps, op);
    },
  }
});

// Saga for WebSocket management
function* documentSyncSaga() {
  const channel = yield call(createWebSocketChannel, '/ws/document');

  // Spawn sender and receiver in parallel
  yield all([
    fork(sendPendingOpsSaga, channel),
    fork(receiveRemoteOpsSaga, channel),
  ]);
}

function* receiveRemoteOpsSaga(channel) {
  while (true) {
    const message = yield take(channel);
    if (message.type === 'operation') {
      yield put(remoteOperation(message));
    } else if (message.type === 'ack') {
      yield put(serverAck(message));
    }
  }
}

function* sendPendingOpsSaga(channel) {
  while (true) {
    yield take([localInsert.type, localDelete.type]);
    const { pendingOps } = yield select(state => state.document);
    const lastOp = pendingOps[pendingOps.length - 1];
    if (lastOp) yield call(channel.send, lastOp);
  }
}
