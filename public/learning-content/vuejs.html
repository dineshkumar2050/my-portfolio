Vue.js — Comprehensive Learning Reference

1. Overview & Philosophy

Vue.js is a progressive JavaScript framework for building user interfaces. "Progressive" means you can adopt it incrementally — use it as a library to enhance static HTML, or build a full-scale SPA with its ecosystem tools.

Core Design Tenets: Approachability (familiar HTML/CSS/JS), Performant (minimal overhead, optimized VDOM), and Versatile (library to full framework).

When to Choose Vue

  • Gradual adoption into existing HTML/jQuery apps
  • Teams that prefer clear separation of concerns (SFC: template / script / style)
  • Projects needing rapid development with low boilerplate
  • When a gentler learning curve is important for the team

2. Version History

Vue 2.7 "Naruto" (July 2022) — Final Vue 2 minor

  • Backported Composition API (setup(), ref(), reactive(), etc.) from Vue 3
  • <script setup> sugar available in SFCs
  • defineProps / defineEmits usable in Vue 2 SFCs
  • Vue 2 reached End-of-Life on December 31, 2023

Vue 3.0 "One Piece" (September 2020)

  • Composition API — setup(), ref(), reactive(), computed(), lifecycle hooks
  • Teleport — render content in a different DOM node
  • Fragments — multiple root elements in a component
  • Emits option — explicit emit declaration
  • Multiple v-model — v-model:title, v-model:content
  • Suspense — async component loading with fallback
  • Proxy-based reactivity (replaces Object.defineProperty)
  • Tree-shakeable global APIs

Vue 3.2 "Quintessential Quintuplets" (August 2021)

  • <script setup> stable — compile-time sugar for Composition API in SFCs
  • v-bind in CSS — bind reactive data to CSS custom properties
  • defineCustomElement() — create native Custom Elements from Vue components
  • Performance improvements: 2–3x faster ref(), reactive()
  • New @vue/server-renderer improvements
  • Vite plugin improvements

Vue 3.3 "Rurouni Kenshin" (May 2023)

  • defineModel() (experimental) — simplifies two-way binding macro
  • Generic components — <script setup lang="ts" generic="T">
  • Imported types in defineProps/defineEmits — use external TypeScript interfaces
  • defineSlots() — type-check slot names and props
  • defineOptions() — declare component options without script setup extra block
  • Improved error messages in template compiler

Vue 3.4 "Slam Dunk" (December 2023)

  • defineModel() stable — fully stabilized two-way binding macro
  • v-bind same-name shorthand — :id shorthand for :id="id"
  • Improved reactivity system — computed values only re-trigger when result actually changes
  • Faster template parsing — 2x speed improvement
  • watchEffect cleanup callback via onWatcherCleanup()

3. Options API vs Composition API

Side-by-Side Comparison — Counter Component

Options API

<!-- CounterOptions.vue -->
<template>
  <div>
    <p>Count: {{ count }}</p>
    <p>Double: {{ doubleCount }}</p>
    <button @click="increment">+</button>
    <button @click="decrement">-</button>
    <button @click="reset">Reset</button>
  </div>
</template>

<script>
export default {
  name: 'CounterOptions',
  props: {
    initialValue: {
      type: Number,
      default: 0
    }
  },
  emits: ['change'],
  data() {
    return {
      count: this.initialValue
    }
  },
  computed: {
    doubleCount() {
      return this.count * 2
    }
  },
  watch: {
    count(newVal, oldVal) {
      this.$emit('change', { newVal, oldVal })
    }
  },
  mounted() {
    console.log('Counter mounted with value:', this.count)
  },
  methods: {
    increment() { this.count++ },
    decrement() { this.count-- },
    reset() { this.count = this.initialValue }
  }
}
</script>

Composition API (script setup)

<!-- CounterComposition.vue -->
<template>
  <div>
    <p>Count: {{ count }}</p>
    <p>Double: {{ doubleCount }}</p>
    <button @click="increment">+</button>
    <button @click="decrement">-</button>
    <button @click="reset">Reset</button>
  </div>
</template>

<script setup lang="ts">
import { ref, computed, watch, onMounted } from 'vue'

interface Props {
  initialValue?: number
}

const props = withDefaults(defineProps<Props>(), {
  initialValue: 0
})

const emit = defineEmits<{
  change: [{ newVal: number; oldVal: number }]
}>()

const count = ref(props.initialValue)

const doubleCount = computed(() => count.value * 2)

watch(count, (newVal, oldVal) => {
  emit('change', { newVal, oldVal })
})

onMounted(() => {
  console.log('Counter mounted with value:', count.value)
})

const increment = () => count.value++
const decrement = () => count.value--
const reset = () => (count.value = props.initialValue)
</script>

4. Reactivity System

How Vue 3 Reactivity Works Under the Hood

Vue 3 uses JavaScript Proxy objects to intercept get/set operations on reactive data. When you access a property in a reactive context (inside computed, watch, or the template), Vue tracks that as a dependency. When the property changes, Vue triggers all dependent effects.

graph LR A["ref() / reactive()"] -->|"Proxy wraps"| B["Reactive Object"] B -->|"get trap → track()"| C["Dependency Tracker"] C -->|"stores"| D["Active Effect (computed/watch/render)"] B -->|"set trap → trigger()"| E["Scheduler"] E -->|"queues & runs"| D

ref()

import { ref } from 'vue'

// Wraps primitives and objects in a reactive container
const count = ref(0)          // { value: 0 }
const name = ref('Vue')       // { value: 'Vue' }
const user = ref({ age: 25 }) // { value: { age: 25 } }

// Access/mutate with .value in JS
count.value++
name.value = 'Vue 3'

// Auto-unwrapped in templates (no .value needed)
// {{ count }} not {{ count.value }}

// Check if ref
import { isRef, unref } from 'vue'
isRef(count)   // true
unref(count)   // 0 — returns .value if ref, else the value itself

reactive()

import { reactive } from 'vue'

// Deep reactive proxy for objects
const state = reactive({
  count: 0,
  user: { name: 'Alice', age: 30 },
  items: ['a', 'b', 'c']
})

// Access directly (no .value)
state.count++
state.user.name = 'Bob'
state.items.push('d')

// CAUTION: destructuring loses reactivity!
const { count } = state       // BROKEN - count is a plain number
const { count } = toRefs(state) // CORRECT - count is a ref

computed()

import { ref, computed } from 'vue'

const price = ref(100)
const quantity = ref(3)

// Read-only computed
const total = computed(() => price.value * quantity.value)

// Writable computed
const firstName = ref('John')
const lastName = ref('Doe')
const fullName = computed({
  get: () => `${firstName.value} ${lastName.value}`,
  set: (val) => {
    [firstName.value, lastName.value] = val.split(' ')
  }
})

fullName.value = 'Jane Smith'
// firstName.value === 'Jane', lastName.value === 'Smith'

// Vue 3.4 improvement: computed only triggers dependents
// when the VALUE ACTUALLY CHANGES (not just re-runs)
const isEven = computed(() => price.value % 2 === 0)
// watchers on isEven only re-run when parity changes

watch()

import { ref, reactive, watch } from 'vue'

const count = ref(0)
const state = reactive({ name: 'Alice' })

// Watch a ref
watch(count, (newVal, oldVal) => {
  console.log(`count: ${oldVal} → ${newVal}`)
})

// Watch a getter (for reactive properties)
watch(() => state.name, (newName) => {
  console.log('Name changed to:', newName)
})

// Watch multiple sources
watch([count, () => state.name], ([newCount, newName], [oldCount, oldName]) => {
  console.log('Either changed')
})

// Options
watch(count, handler, {
  immediate: true,      // Run immediately on creation
  deep: true,           // Deep watch nested objects
  once: true,           // Auto-stop after first trigger (Vue 3.4+)
  flush: 'post'         // Run after DOM updates ('pre' | 'post' | 'sync')
})

// Stop a watcher
const stop = watch(count, handler)
stop() // Stops watching

watchEffect()

import { ref, watchEffect } from 'vue'

const userId = ref(1)

// Automatically tracks dependencies used inside
const stop = watchEffect(async (onCleanup) => {
  const controller = new AbortController()

  // Cleanup for previous run (cancel previous request)
  onCleanup(() => controller.abort())

  const data = await fetch(`/api/user/${userId.value}`, {
    signal: controller.signal
  })
  // ...
})

// Vue 3.4+: onWatcherCleanup() outside the callback
import { onWatcherCleanup } from 'vue'
watchEffect(() => {
  const timer = setTimeout(() => {}, 200)
  onWatcherCleanup(() => clearTimeout(timer))
})

stop() // Stop the effect

Other Reactivity Utilities

import {
  readonly, shallowRef, shallowReactive,
  toRef, toRefs, markRaw, triggerRef
} from 'vue'

// readonly - prevents mutations (but tracks reactivity)
const original = reactive({ count: 0 })
const readonlyState = readonly(original)
// readonlyState.count++ // Warning in dev mode

// shallowRef - only .value itself is reactive (no deep)
const shallowUser = shallowRef({ name: 'Alice', address: { city: 'NY' } })
shallowUser.value.address.city = 'LA' // NOT reactive
shallowUser.value = { name: 'Bob', address: { city: 'LA' } } // IS reactive

// shallowReactive - only top-level properties are reactive
const shallowState = shallowReactive({
  user: { name: 'Alice' }
})
shallowState.user = { name: 'Bob' }  // IS reactive
shallowState.user.name = 'Charlie'   // NOT reactive

// toRef - create a ref linked to a reactive property
const state = reactive({ count: 0 })
const countRef = toRef(state, 'count')
// Mutating countRef.value also mutates state.count

// toRefs - convert entire reactive object to refs
const { count, name } = toRefs(state)

// markRaw - exclude from reactivity system
const rawObject = markRaw({ hugeData: [...] })

// triggerRef - manually trigger a shallowRef's effects
triggerRef(shallowUser)

7. <script setup>

<script setup> is compile-time syntactic sugar for using the Composition API in Single-File Components. It is the recommended approach for Vue 3 SFCs.

All Compiler Macros

<script setup lang="ts">
import { ref, computed } from 'vue'

// 1. defineProps — declare component props
interface Props { name: string; age?: number }
const props = withDefaults(defineProps<Props>(), { age: 0 })

// 2. defineEmits — declare component events
const emit = defineEmits<{
  update: [value: string]
}>()

// 3. defineModel — two-way binding (Vue 3.4 stable)
const modelValue = defineModel<string>()
// equivalent to: v-model passes :modelValue + @update:modelValue
const count = defineModel<number>('count', { default: 0 })

// 4. defineExpose — expose properties to parent refs
const publicData = ref('exposed')
const publicMethod = () => 'hello from child'
defineExpose({ publicData, publicMethod })

// 5. defineSlots — type-check slots
const slots = defineSlots<{
  default(props: { item: string }): unknown
  header(props: {}): unknown
}>()

// 6. defineOptions — set component options (Vue 3.3+)
defineOptions({
  name: 'MyComponent',
  inheritAttrs: false
})

// 7. useAttrs — access fallthrough attributes
import { useAttrs } from 'vue'
const attrs = useAttrs() // { class, style, ...non-prop attrs }

// 8. useSlots — access slots programmatically
import { useSlots } from 'vue'
const slotsRef = useSlots()
const hasHeader = computed(() => !!slotsRef.header)
</script>

8. Composables

The useXxx Pattern

// composables/useFetch.ts
import { ref, watchEffect, toValue, type MaybeRefOrGetter } from 'vue'

interface FetchState<T> {
  data: Ref<T | null>
  error: Ref<Error | null>
  loading: Ref<boolean>
}

export function useFetch<T>(url: MaybeRefOrGetter<string>): FetchState<T> {
  const data = ref<T | null>(null)
  const error = ref<Error | null>(null)
  const loading = ref(false)

  watchEffect(async (onCleanup) => {
    const controller = new AbortController()
    onCleanup(() => controller.abort())

    loading.value = true
    error.value = null

    try {
      const response = await fetch(toValue(url), {
        signal: controller.signal
      })
      if (!response.ok) throw new Error(response.statusText)
      data.value = await response.json()
    } catch (e) {
      if (e instanceof Error && e.name !== 'AbortError') {
        error.value = e
      }
    } finally {
      loading.value = false
    }
  })

  return { data, error, loading }
}
<!-- Usage -->
<script setup>
import { ref } from 'vue'
import { useFetch } from '@/composables/useFetch'

const userId = ref(1)
const { data: user, loading, error } = useFetch(
  () => `/api/users/${userId.value}`  // reactive URL
)
</script>

Lifecycle Hooks in Composables

// composables/useEventListener.ts
import { onMounted, onUnmounted } from 'vue'

export function useEventListener(
  target: EventTarget | Ref<EventTarget | null>,
  event: string,
  callback: EventListener
) {
  onMounted(() => {
    const el = isRef(target) ? target.value : target
    el?.addEventListener(event, callback)
  })

  onUnmounted(() => {
    const el = isRef(target) ? target.value : target
    el?.removeEventListener(event, callback)
  })
}

// stores/useCartStore.ts
import { ref, computed } from 'vue'
import { defineStore } from 'pinia'

export const useCartStore = defineStore('cart', () => {
  // State (refs)
  const items = ref<CartItem[]>([])
  const isLoading = ref(false)

  // Getters (computed)
  const totalItems = computed(() =>
    items.value.reduce((sum, item) => sum + item.quantity, 0)
  )
  const totalPrice = computed(() =>
    items.value.reduce((sum, item) => sum + item.price * item.quantity, 0)
  )

  // Actions (functions)
  async function fetchCart(userId: string) {
    isLoading.value = true
    try {
      items.value = await api.getCart(userId)
    } finally {
      isLoading.value = false
    }
  }

  function addItem(product: Product, quantity = 1) {
    const existing = items.value.find(i => i.id === product.id)
    if (existing) {
      existing.quantity += quantity
    } else {
      items.value.push({ ...product, quantity })
    }
  }

  function removeItem(productId: string) {
    items.value = items.value.filter(i => i.id !== productId)
  }

  function clearCart() {
    items.value = []
  }

  return {
    items, isLoading,
    totalItems, totalPrice,
    fetchCart, addItem, removeItem, clearCart
  }
})

Q1. What is the difference between v-show and v-if? Easy

v-if conditionally renders the element — it's completely removed from the DOM when false. It also tears down and re-creates event listeners and child components.

v-show always renders the element but toggles its display CSS property. The element always stays in the DOM.

Q2. What is the Vue reactivity system and how does ref() differ from reactive()? Easy

Vue 3 uses Proxy to intercept property access and mutations on reactive objects, enabling automatic dependency tracking.

ref() wraps any value (primitive or object) in a reactive container. You access the value via .value in JavaScript but it's auto-unwrapped in templates.

reactive() returns a deep reactive proxy of an object. No .value needed, but only works with objects (not primitives), and loses reactivity if destructured.

// ref — works with any type
const count = ref(0)
count.value++  // Access with .value

// reactive — objects only
const state = reactive({ count: 0 })
state.count++  // Access directly

// Destructuring reactive loses reactivity
const { count } = state        // BROKEN
const { count } = toRefs(state) // CORRECT

Rule of thumb: Use ref() for primitives and simple values; either works for objects, but ref() is preferred in <script setup> for consistency.

Q3. What are Vue Single File Components (SFCs)? Easy

SFCs are files with a .vue extension that encapsulate a component's template, logic, and styles in a single file. They are compiled by tools like Vite or Vue CLI.

Q5. What is v-model and how does it work on custom components? Easy

v-model is syntactic sugar for a value binding + event listener. On native inputs:

<!-- v-model on input -->
<input v-model="text">
<!-- is equivalent to: -->
<input :value="text" @input="text = $event.target.value">

On custom components, v-model binds modelValue prop + listens for update:modelValue event:

<!-- Usage -->

<!-- is equivalent to: -->

<template>
  <input :value="model" @input="model = $event.target.value">
</template>

Q10. How do Vue composables work and what are the rules for using them? Intermediate

Composables are functions that use Vue's Composition API to encapsulate and reuse stateful logic. They follow the useXxx naming convention.

Rules:

  • Must be called from setup() or <script setup> (or another composable)
  • Must be called synchronously (no conditional calls)
  • Lifecycle hooks inside composables attach to the calling component instance
// CORRECT — called synchronously in setup
export function useMouse() {
  const x = ref(0), y = ref(0)

  onMounted(() => window.addEventListener('mousemove', update))
  onUnmounted(() => window.removeEventListener('mousemove', update))

  function update(e) { x.value = e.x; y.value = e.y }

  return { x, y }
}

// In component
const { x, y } = useMouse()  // Called synchronously in setup

// WRONG — conditional call
if (condition) {
  const { x } = useMouse()  // Never do this
}

Advanced Questions

Q11. How does Vue 3's Proxy-based reactivity differ from Vue 2's Object.defineProperty approach? Advanced

Vue 2 used Object.defineProperty to intercept property access, which had several limitations:

  • Could not detect property addition or deletion (required Vue.set/Vue.delete)
  • Could not detect array index assignments (arr[0] = val) or .length mutations
  • Required traversing the entire object at initialization (performance cost)

Vue 3 uses Proxy which intercepts all operations on an object:

// Vue 3 simplified reactivity internals
function reactive(raw) {
  return new Proxy(raw, {
    get(target, key, receiver) {
      // Track: record that current effect depends on this property
      track(target, key)
      return Reflect.get(target, key, receiver)
    },
    set(target, key, value, receiver) {
      const result = Reflect.set(target, key, value, receiver)
      // Trigger: notify all effects that depend on this property
      trigger(target, key)
      return result
    },
    deleteProperty(target, key) {
      const result = Reflect.deleteProperty(target, key)
      trigger(target, key)
      return result
    }
    // also: has, ownKeys, etc.
  })
}

// Now these work in Vue 3:
const state = reactive({ items: [] })
state.newProp = 'works!'     // Detects new property
delete state.newProp          // Detects deletion
state.items[0] = 'works!'    // Detects array index
state.items.length = 0        // Detects length change

Proxy also enables lazy/on-demand reactivity (nested objects become reactive only when accessed), improving initial performance.

Q12. What is the virtual DOM in Vue, and how does Vue's compiler optimize it? Advanced

The Virtual DOM (VDOM) is a JavaScript representation of the actual DOM tree. Vue diffs the new VDOM against the previous one and only updates changed nodes — avoiding expensive full DOM re-renders.

Vue 3's compiler performs static analysis at compile time to generate highly optimized render functions:

  • Static hoisting: Pure static nodes are hoisted outside the render function (created once, not re-created each render)
  • Patch flags: Dynamic nodes are tagged with a bitfield indicating what changed (text only? props only?), so the diffing only checks what can change
  • Block tree optimization: Dynamic nodes within a block are tracked in a flat array, skipping stable static subtrees entirely
// Template:
// <div>
//   <p>Static text</p>  <!-- hoisted -->
//   <p>{{ dynamic }}</p> <!-- patch flag: TEXT (1) -->
//   <div :id="dynamicId">...</div> <!-- patch flag: PROPS (8) -->
// </div>

// Compiled render function (simplified):
const _hoisted_1 = createElementVNode("p", null, "Static text")

function render() {
  return createElementBlock("div", null, [
    _hoisted_1,   // Reused, not recreated
    createElementVNode("p", null, toDisplayString(dynamic), 1 /* TEXT */),
    createElementVNode("div", { id: dynamicId }, null, 8 /* PROPS */)
  ])
}
Q13. How do you implement server-side rendering (SSR) with Vue and Nuxt? Advanced

Vue supports SSR natively via @vue/server-renderer. Nuxt is the meta-framework that handles SSR, file-based routing, auto-imports, and more.

// Raw Vue SSR (server entry)
import { createSSRApp } from 'vue'
import { renderToString } from '@vue/server-renderer'
import App from './App.vue'

export async function render(url, manifest) {
  const app = createSSRApp(App)

  // Create fresh router, store per request
  const router = createRouter()
  const pinia = createPinia()
  app.use(router).use(pinia)

  await router.push(url)
  await router.isReady()

  const ctx = {}
  const html = await renderToString(app, ctx)
  return { html, state: pinia.state.value }
}

SSR caveats:

  • No access to browser APIs (window, document, localStorage) during server render
  • Guard with if (process.client) / if (!import.meta.env.SSR)
  • Components are created fresh per request — avoid global mutable state
  • Use onMounted for browser-only code (doesn't run on server)
  • Hydration: client-side Vue takes over server-rendered HTML (createSSRApp instead of createApp)

Nuxt 3 rendering modes:

// nuxt.config.ts

Q14. How does provide/inject work, and what are the best practices for typed injection? Advanced

provide() makes data available to any descendant component (avoids prop drilling). inject() retrieves it. The key best practice is using typed InjectionKey symbols for type safety.

// keys.ts — centralized injection keys
import type { InjectionKey, Ref } from 'vue'

export interface UserContext {
  user: Ref<User | null>
  isAuthenticated: Ref<boolean>
  login: (creds: Credentials) => Promise<void>
  logout: () => void
}

export const userContextKey: InjectionKey<UserContext> = Symbol('userContext')

// AuthProvider.vue
import { provide, ref } from 'vue'
import { userContextKey } from './keys'

const user = ref<User | null>(null)
const isAuthenticated = ref(false)

provide(userContextKey, {
  user, isAuthenticated,
  login: async (creds) => { /* ... */ },
  logout: () => { user.value = null; isAuthenticated.value = false }
})

// Any descendant
import { inject } from 'vue'
import { userContextKey } from './keys'

// Fully typed, no need for type assertion
const { user, login, logout } = inject(userContextKey)!

// With default value (when provider might not exist)
const ctx = inject(userContextKey, {
  user: ref(null),
  isAuthenticated: ref(false),
  login: async () => {},
  logout: () => {}
})

Reactivity with provide/inject: To maintain reactivity, provide refs/reactive objects, not their raw values. To prevent mutation of provided data from descendants, wrap with readonly().

Q15. Explain the difference between Teleport and KeepAlive and their internal implementation details. Advanced

Teleport moves the component's rendered DOM to a different place in the document, while keeping its logical position in the component tree (parent-child relationships, provide/inject, event handling all work normally).

<!-- Even though Portal renders inside App component tree,
     its DOM appears inside #portal-target -->
<Teleport to="#portal-target" :disabled="isMobile">
  <Modal v-if="showModal" />
</Teleport>

<!-- Multiple Teleports to same target are appended in order -->
<Teleport to="body"><Toast msg="First" /></Teleport>
<Teleport to="body"><Toast msg="Second" /></Teleport>

KeepAlive caches component instances when they are conditionally unmounted. Instead of destroying the component, it moves it to an internal cache, preserving state.

<KeepAlive
  :include="/^(UserProfile|Dashboard)$/"
  :exclude="['TempComponent']"
  :max="10"
>
  <component :is="currentTab" />
</KeepAlive>
  • include/exclude: String, RegExp, or Array — matches component name
  • max: LRU eviction when cache exceeds limit
  • Cached components trigger onActivated/onDeactivated instead of onMounted/onUnmounted

  // Insert into parent
  insert(child, parent, anchor) {
    const index = anchor ? parent.children.indexOf(anchor) : parent.children.length
    parent.children.splice(index, 0, child)
  },

  // Remove from parent
  remove(child) {
    const parent = child.parentNode
    if (parent) {
      parent.children.splice(parent.children.indexOf(child), 1)
    }
  },

  // Other required methods
  createComment: (text) => ({ type: 'comment', text }),
  setText: (node, text) => { node.content = text },
  setElementText: (el, text) => { el.textContent = text },
  parentNode: (node) => node.parentNode,
  nextSibling: (node) => {
    const siblings = node.parentNode?.children ?? []
    return siblings[siblings.indexOf(node) + 1] ?? null
  }
})

// Use like regular Vue
const app = createApp(CanvasApp)
app.mount(canvasElement)

Q17. Explain Vue's scheduler and how it batches DOM updates. Very Advanced

Vue batches reactive updates using a microtask queue (via Promise.then or MutationObserver). When reactive data changes, re-renders are not immediate — they're scheduled to run after the current synchronous code finishes.

// Simplified scheduler internals
const queue: SchedulerJob[] = []
let isFlushing = false

function queueJob(job) {
  if (!queue.includes(job)) {
    queue.push(job)
  }
  queueFlush()
}

function queueFlush() {
  if (!isFlushing) {
    isFlushing = true
    Promise.resolve().then(flushJobs)  // Microtask
  }
}

function flushJobs() {
  // Sort by component ID (parent before child = parent renders first)
  queue.sort((a, b) => a.id - b.id)

  try {
    for (let i = 0; i < queue.length; i++) {
      const job = queue[i]
      job()  // Run component re-render / watcher callback
    }
  } finally {
    queue.length = 0
    isFlushing = false
  }
}
// Practical consequence: multiple synchronous changes = ONE re-render
count.value = 1
count.value = 2
count.value = 3
// Component re-renders ONCE with count = 3, not 3 times

// nextTick: wait for pending DOM updates
import { nextTick } from 'vue'

async function onClick() {
  items.value.push(newItem)
  await nextTick()  // Wait for DOM update
  // Now DOM reflects the new item — safe to measure, scroll, etc.
  const lastEl = listRef.value?.lastElementChild
  lastEl?.scrollIntoView()
}

// flush: 'sync' watcher bypasses scheduler — runs synchronously
watch(count, handler, { flush: 'sync' }) // Dangerous — use sparingly
Q18. How does Vue's template compiler work, and how can you write custom compiler transforms? Very Advanced

Vue's template compiler transforms HTML templates into optimized render functions in 3 phases:

  1. Parse: HTML → Abstract Syntax Tree (AST) — @vue/compiler-core
  2. Transform: Apply AST transforms (v-if, v-for, directives, static analysis)
  3. Codegen: AST → JavaScript render function string
import { parse, transform, generate } from '@vue/compiler-core'

// Write a custom transform plugin
const myTransform = {
  // Called for every node in the AST
  transformElement(node, context) {
    if (node.type === 1 /* ELEMENT */ && node.tag === 'my-tag') {
      // Modify the AST node
      node.tag = 'div'
      node.props.push({
        type: 6, // ATTRIBUTE
        name: 'data-my-tag',
        value: { type: 2, content: 'true' }
      })
    }
  }
}

// Use in Vite plugin
import { Plugin } from 'vite'
import { compileTemplate } from '@vue/compiler-sfc'

export function myVuePlugin(): Plugin {
  return {
    name: 'my-vue-transform',
    transform(code, id) {
      if (!id.endsWith('.vue')) return

    }
  }
}

import type { App, Plugin } from 'vue'

}

export const MyPlugin: Plugin = {
  install(app: App, options: MyPluginOptions) {
    const api: MyPluginApi = {
      track: (event, data) => {
        if (options.debug) console.log('[MyPlugin] track', event, data)
        fetch(`${options.baseUrl}/track`, {
          method: 'POST',
          body: JSON.stringify({ event, data, key: options.apiKey })
        })
      },
      identify: (userId) => { /* ... */ }
    }

    // Global property
    app.config.globalProperties.$myPlugin = api

    // Provide for Composition API usage
    app.provide('myPlugin', api)

    // Global component
    app.component('MyButton', MyButton)

    // Global directive
    app.directive('track', {
      mounted(el, binding) {
        el.addEventListener('click', () => api.track(binding.value))
      }
    })

    app.mixin({
      mounted() {
        const options = (this.$options as any).myPluginOptions
        if (options?.trackMount) {
          api.track('component_mounted', { name: this.$options.name })
        }
      }
    })
  }
}

// Composable for Composition API consumers
export function useMyPlugin(): MyPluginApi {
  const api = inject<MyPluginApi>('myPlugin')
  if (!api) throw new Error('MyPlugin not installed')
  return api
}

import { defineCustomElement, h, ref } from 'vue'

const MyCounter = defineCustomElement({
  props: ['initialValue'],
  emits: ['change'],
  styles: ['.counter { display: flex; gap: 8px; }'],  // Injected into Shadow DOM

  setup(props, { emit }) {
    const count = ref(parseInt(props.initialValue) || 0)

    function increment() {
      count.value++
      emit('change', count.value)
    }

    return () => h('div', { class: 'counter' }, [
      h('button', { onClick: () => count.value-- }, '-'),
      h('span', count.value),
      h('button', { onClick: increment }, '+')
    ])
  }
})
