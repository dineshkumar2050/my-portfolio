1. Data Types & Variables

JavaScript has 7 primitives (string, number, bigint, boolean, undefined, null, symbol) stored by value, and one reference type (objects/arrays/functions) stored by reference. Primitives are immutable; reference types can be mutated in place. typeof null === "object" is a historic bug.

var / let / const hoisting

var declarations are hoisted to function scope and initialised to undefined. let and const are hoisted to block scope but sit in a Temporal Dead Zone (TDZ) until the declaration line — accessing them before that throws a ReferenceError. const prevents rebinding but not mutation of the referenced object.

console.log(a); // undefined (var hoisted)
var a = 10;

// console.log(b); // ReferenceError: TDZ
let b = 20;

const obj = { x: 1 };
obj.x = 2;        // OK — mutation allowed
// obj = {};      // TypeError — rebinding not allowed

Type Coercion — == vs ===

== applies abstract equality with implicit coercion rules (e.g., "5" == 5 is true). === requires the same type and value with no coercion. Always prefer === to avoid surprising results. Use explicit conversions (Number(), String(), Boolean()) when type conversion is intentional.

console.log(0 == false);    // true  (coercion)
console.log(0 === false);   // false (different types)
console.log(null == undefined); // true
console.log(null === undefined);// false
console.log(NaN === NaN);   // false — use Number.isNaN()
console.log([] == false);   // true — [] → "" → 0, false → 0

2. Functions

Function declarations are fully hoisted (name + body). Function expressions and arrow functions are not hoisted. Arrow functions capture this lexically from their enclosing scope; they cannot be used as constructors and have no arguments object.

Declaration vs Expression vs Arrow

// Declaration — hoisted
function greet(name) { return `Hello, ${name}`; }

// Expression — NOT hoisted
const greetExp = function(name) { return `Hi, ${name}`; };

// Arrow — lexical this, concise body
const greetArr = name => `Hey, ${name}`;

// Arrow cannot be a constructor
// new greetArr(); // TypeError

Closure — Counter Example

A closure is a function that retains access to its outer scope even after the outer function returns. The inner function "closes over" the variables of its parent. This is the foundation of data encapsulation in JavaScript.

function makeCounter(start = 0) {
  let count = start;
  return {
    increment: () => ++count,
    decrement: () => --count,
    value:     () => count,
  };
}
const c = makeCounter(10);
c.increment(); c.increment();
console.log(c.value()); // 12

IIFE

const result = (function() {
  const private = "hidden";
  return { get: () => private };
})();
console.log(result.get()); // "hidden"
// console.log(private);   // ReferenceError

3. Scope & Closures

JavaScript uses lexical (static) scoping — the scope of a variable is determined by where it is written in source code, not where it is called from. Each function creates a new scope. Block statements (if, for) create block scope for let/const but not for var.

Closure in Loops — var vs let

Classic loop gotcha: var shares one binding across all iterations. let creates a fresh binding per iteration, fixing the closure-in-loop bug without needing an IIFE workaround.

// var — all callbacks share the SAME `i`
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log("var:", i), 0); // 3, 3, 3
}

// let — each iteration gets its OWN binding
for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log("let:", j), 0); // 0, 1, 2
}

4. The this Keyword

The value of this depends on call-site context, not where the function is defined — except for arrow functions which inherit this from their enclosing lexical scope at definition time. In strict mode the default binding (standalone call) is undefined instead of the global object.

call / apply / bind

function introduce(greeting, punct) {
  return `${greeting}, I'm ${this.name}${punct}`;
}
const user = { name: "Alice" };

introduce.call(user, "Hello", "!");   // "Hello, I'm Alice!"
introduce.apply(user, ["Hi", "."]);   // "Hi, I'm Alice."
const bound = introduce.bind(user, "Hey");
bound("?"); // "Hey, I'm Alice?"

Arrow vs Regular in Object

const obj = {
  name: "Bob",
  regular() { return this.name; },       // "Bob"
  arrow: () => obj.name,                 // "Bob" (closes over outer)
  broken: () => this?.name ?? "undefined", // undefined in module scope
};

5. Prototypes & Classes

Every object has an internal [[Prototype]] link. Property lookups traverse the chain until found or until null is reached. ES6 classes are syntactic sugar over prototype-based inheritance — no new runtime mechanism, just cleaner syntax.

Object.create() and the chain

const animal = { breathe() { return "inhale/exhale"; } };
const dog = Object.create(animal);
dog.bark = () => "Woof!";

console.log(dog.breathe()); // found on prototype
console.log(Object.getPrototypeOf(dog) === animal); // true

ES6 Class with extends / super

class Shape {
  constructor(color) { this.color = color; }
  describe() { return `A ${this.color} shape`; }
}
class Circle extends Shape {
  constructor(color, r) { super(color); this.r = r; }
  area() { return Math.PI * this.r ** 2; }
  describe() { return `${super.describe()} (circle r=${this.r})`; }
}
const c = new Circle("red", 5);
console.log(c.area().toFixed(2)); // 78.54

6. Event Loop

JavaScript is single-threaded. The event loop picks tasks from queues and pushes them onto the call stack when the stack is empty. Microtasks (Promise callbacks, queueMicrotask) drain completely after each task before the next macrotask (setTimeout, setInterval, I/O) runs. This means Promises resolve before timers even if timers were set first.

flowchart LR subgraph Runtime CS["Call Stack"] WEB["Web APIs / Node APIs"] end subgraph Queues MQ["Microtask Queue\n(Promise.then, queueMicrotask)"] CQ["Callback Queue (Macrotask)\n(setTimeout, setInterval, I/O)"] end CS -- "async op" --> WEB WEB -- "resolved" --> MQ WEB -- "timer / I/O done" --> CQ MQ -- "drain all microtasks\n(after each task)" --> CS CQ -- "one task at a time\n(when stack empty)" --> CS 
console.log("1 — sync");

setTimeout(() => console.log("4 — macrotask"), 0);

Promise.resolve()
  .then(() => console.log("2 — microtask 1"))
  .then(() => console.log("3 — microtask 2"));

console.log("1b — still sync");
// Output order: 1, 1b, 2, 3, 4

7. Promises & Async/Await

A Promise represents an eventual value and is in one of three immutable states: pending, fulfilled, or rejected. Once settled it never changes. async/await is syntactic sugar over Promises that makes asynchronous code look synchronous without blocking the thread.

Promise combinators

const p1 = Promise.resolve(1);
const p2 = Promise.resolve(2);
const p3 = Promise.reject("err");

// all — rejects on first rejection
await Promise.all([p1, p2]);            // [1, 2]

// allSettled — waits for all, never rejects
await Promise.allSettled([p1, p3]);
// [{status:"fulfilled",value:1},{status:"rejected",reason:"err"}]

// race — first settled wins
await Promise.race([p1, p2]);           // 1

async / await with error handling

async function fetchUser(id) {
  try {
    const res = await fetch(`/api/users/${id}`);
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return await res.json();
  } catch (err) {
    console.error("Fetch failed:", err.message);
    return null;
  } finally {
    console.log("Always runs");
  }
}

8. ES6+ Features

Modern JavaScript provides concise syntax improvements that reduce boilerplate and improve readability. Key additions include destructuring, spread/rest operators, template literals, optional chaining, nullish coalescing, and Symbol for unique identifiers.

Destructuring & Rest/Spread

const { name, age = 25, ...rest } = { name: "Ana", age: 30, city: "NY" };
const [first, , third] = [10, 20, 30];

const merged = { ...rest, active: true };   // spread into new object
const nums   = [...[1,2], ...[3,4]];        // spread into array

Optional chaining & Nullish coalescing

const user = { profile: { address: null } };

const city   = user?.profile?.address?.city ?? "Unknown";
const method = user?.getAge?.();  // undefined (no error)
const arr    = user?.tags?.[0];   // undefined (no error)

console.log(city); // "Unknown"

Symbol

const id  = Symbol("id");
const obj = { [id]: 42, name: "test" };

console.log(obj[id]);                     // 42
console.log(Object.keys(obj));            // ["name"] — Symbol hidden
console.log(Symbol("x") === Symbol("x")); // false — always unique

9. Iterators & Generators

An iterable is any object with a [Symbol.iterator] method returning an iterator (an object with next() that yields { value, done }). Generator functions (function*) simplify writing iterators by pausing at each yield. They enable lazy, on-demand sequences including infinite ones.

Custom iterable & infinite generator

function* naturals(start = 1) {
  while (true) yield start++;
}

const gen = naturals();
console.log(gen.next().value); // 1
console.log(gen.next().value); // 2

// Take first n values
function take(iter, n) {
  const result = [];
  for (const val of iter) {
    result.push(val);
    if (result.length === n) break;
  }
  return result;
}
console.log(take(naturals(5), 4)); // [5,6,7,8]

10. Modules

CommonJS (require/module.exports) is synchronous and used in Node.js by default — it evaluates the entire module on first require and caches the result. ES Modules (import/export) are static, asynchronous, and tree-shakeable. Dynamic import() returns a Promise enabling code-splitting.

// CommonJS (Node.js)
const fs = require("fs");
module.exports = { readFile: fs.readFileSync };

// ES Module (static)
import { readFile } from "fs/promises";
export const double = x => x * 2;
export default class App {}

// Dynamic import (lazy loading)
const { heavy } = await import("./heavy-module.js");
Use "type": "module" in package.json to enable ESM in Node.js. ESM files use .mjs extension by default when type is not set.

11. Error Handling

try/catch/finally handles synchronous errors and works with await inside async functions. The finally block always runs regardless of success or failure and is ideal for cleanup. Custom error classes (extending Error) allow meaningful type checking with instanceof.

class ValidationError extends Error {
  constructor(field, message) {
    super(message);
    this.name = "ValidationError";
    this.field = field;
  }
}

function validateAge(age) {
  if (typeof age !== "number") throw new ValidationError("age", "Must be a number");
  if (age < 0 || age > 150)   throw new ValidationError("age", "Out of range");
  return age;
}

try {
  validateAge("old");
} catch (e) {
  if (e instanceof ValidationError) console.error(`Field: ${e.field} — ${e.message}`);
  else throw e; // re-throw unexpected errors
}

12. DOM Basics

The DOM API lets JavaScript read and modify HTML structure, styles, and content. Event listeners can be attached in the capture phase (root → target) or bubble phase (target → root). The fetch API is Promise-based and replaces XMLHttpRequest for HTTP requests.

Event bubbling vs capturing

// Capturing (3rd arg true) runs parent before child
document.getElementById("parent").addEventListener("click", () => {
  console.log("parent capture");
}, true);

// Bubbling (default) runs child before parent
document.getElementById("child").addEventListener("click", e => {
  console.log("child bubble");
  e.stopPropagation(); // stops event from bubbling further
});

fetch API

async function postData(url, body) {
  const res = await fetch(url, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(body),
  });
  if (!res.ok) throw new Error(`HTTP ${res.status}: ${res.statusText}`);
  return res.json();
}

13. Patterns

Debounce

Delays execution until a burst of calls stops. Useful for search-as-you-type inputs where you want to wait until the user pauses typing before firing the expensive request.

function debounce(fn, delay) {
  let timer;
  return function(...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}
const search = debounce(q => console.log("search:", q), 300);

Throttle

Guarantees a function fires at most once per interval. Useful for scroll/resize handlers where you want regular updates but not on every pixel change.

function throttle(fn, limit) {
  let inThrottle = false;
  return function(...args) {
    if (!inThrottle) {
      fn.apply(this, args);
      inThrottle = true;
      setTimeout(() => (inThrottle = false), limit);
    }
  };
}
const onScroll = throttle(() => console.log("scroll"), 200);

Memoize

Caches results of pure function calls keyed by arguments. Subsequent calls with the same arguments return the cached value immediately, trading memory for speed.

function memoize(fn) {
  const cache = new Map();
  return function(...args) {
    const key = JSON.stringify(args);
    if (cache.has(key)) return cache.get(key);
    const result = fn.apply(this, args);
    cache.set(key, result);
    return result;
  };
}
const fib = memoize(n => n <= 1 ? n : fib(n-1) + fib(n-2));

Observer Pattern

class EventEmitter {
  #listeners = {};
  on(event, fn)  { (this.#listeners[event] ??= []).push(fn); return this; }
  off(event, fn) { this.#listeners[event] = (this.#listeners[event] ?? []).filter(l => l !== fn); }
  emit(event, ...args) { (this.#listeners[event] ?? []).forEach(fn => fn(...args)); }
}
const bus = new EventEmitter();
bus.on("data", d => console.log("got:", d));
bus.emit("data", { id: 1 }); // got: {id:1}

14. Performance

WeakMap vs Map

WeakMap holds weak references to its keys (must be objects) so they can be garbage-collected when no other references remain. Map keeps strong references, preventing GC. Use WeakMap for caching data associated with DOM nodes or objects you don't own.

const cache = new WeakMap();

function process(domNode) {
  if (cache.has(domNode)) return cache.get(domNode);
  const result = expensiveOp(domNode);
  cache.set(domNode, result);  // released when domNode is GC'd
  return result;
}
// Map equivalent would prevent GC of domNode

Memory Leak Example

// LEAK: event listener keeps 'data' alive via closure
function attach(el) {
  const data = new Array(1e5).fill("x");
  el.addEventListener("click", () => console.log(data.length));
  // Fix: remove listener when done
  // return () => el.removeEventListener("click", handler);
}

requestAnimationFrame

requestAnimationFrame schedules work before the next repaint, running at the display's refresh rate (~60fps). Prefer it over setInterval for animations as it pauses when the tab is hidden, saving CPU.

function animate(el) {
  let x = 0;
  function step() {
    x = (x + 1) % 300;
    el.style.transform = `translateX(${x}px)`;
    requestAnimationFrame(step); // ~60fps, pauses in background tabs
  }
  requestAnimationFrame(step);
}

15. Common Gotchas

Floating-point arithmetic

JavaScript numbers are IEEE 754 double-precision. Decimal arithmetic is not exact. Use integer math or a library like decimal.js for financial calculations, and always compare with a tolerance (epsilon) rather than strict equality.

console.log(0.1 + 0.2 === 0.3); // false — 0.30000000000000004
console.log(Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON); // true

// Safe integer range
console.log(Number.MAX_SAFE_INTEGER); // 9007199254740991
const big = 9007199254740993n;        // BigInt avoids this

Array sort is lexicographic by default

Array.prototype.sort converts elements to strings for comparison by default. Always pass a comparator for numeric or custom sorting. Without one, [10, 9, 2].sort() yields [10, 2, 9] — the most common sort bug.

const nums = [10, 1, 9, 2];
nums.sort();                        // [1, 10, 2, 9] — WRONG
nums.sort((a, b) => a - b);        // [1, 2, 9, 10] — correct asc
nums.sort((a, b) => b - a);        // [10, 9, 2, 1] — correct desc

Mutable default arguments in functions

Assigning a mutable object as a default parameter value creates a single shared object across all calls (in Python this is notorious; in JS it only matters for objects/arrays). Use a factory default instead.

// Bug: all callers share the SAME array
function addItem(item, list = []) {
  list.push(item);
  return list;
}
// Fix: produce a new array each call
function addItemSafe(item, list) {
  list = list ? [...list] : [];
  list.push(item);
  return list;
}

async forEach does NOT await

Array.forEach ignores the returned Promise from an async callback — the loop runs to completion before any awaited work finishes. Use for...of for sequential async iteration or Promise.all(arr.map(...)) for parallel.

// WRONG — forEach doesn't await
items.forEach(async item => { await process(item); });

// Sequential
for (const item of items) { await process(item); }

// Parallel
await Promise.all(items.map(item => process(item)));

Q&A — 15 Interview Questions

Easy

What is hoisting? How does var differ from let/const? Easy

Hoisting is JavaScript's behavior of moving declarations to the top of their scope during compilation. var declarations are hoisted to function scope and initialised to undefined, so you can read them before the line without a ReferenceError (you just get undefined).

let and const are hoisted to block scope but remain in the Temporal Dead Zone (TDZ) until execution reaches the declaration. Accessing them before that point throws a ReferenceError. Function declarations are fully hoisted (name + body), meaning you can call them before they appear in source.

console.log(x); // undefined — var hoisted
var x = 5;

console.log(y); // ReferenceError — TDZ
let y = 5;
What is the difference between == and ===? Easy

=== (strict equality) checks both value and type with no conversion. == (abstract equality) applies a set of type-coercion rules: if the types differ, JavaScript converts one or both operands before comparing.

Key coercion rules for ==: null == undefined is true; a string compared to a number converts the string; false becomes 0; objects call valueOf/toString. Always use === unless you specifically need coercion.

0 == "0"    // true  — string coerced to number
0 === "0"   // false — different types
null == undefined  // true
null === undefined // false
What is a closure and why is it useful? Easy

A closure is a function that remembers and accesses variables from its enclosing lexical scope even after that outer function has returned. The inner function "closes over" those variables, keeping them alive in memory.

Closures enable data privacy (encapsulating state), partial application (fixing some arguments), and the module pattern. They are the mechanism behind counters, factory functions, and memoisation.

function multiplier(factor) {
  return n => n * factor; // closes over `factor`
}
const triple = multiplier(3);
console.log(triple(5)); // 15 — `factor` still accessible
What is the difference between null and undefined? Easy

undefined means a variable has been declared but not assigned, or a function parameter was not provided, or an object property doesn't exist. It is the JS engine's default "nothing". null is an explicit, intentional absence of a value — you set it on purpose.

typeof undefined === "undefined"; typeof null === "object" (historic bug). Both are falsy. Both equal each other with == but not with ===. Use nullish coalescing (??) to handle both: val ?? "default".

Intermediate

Explain the JavaScript Event Loop. What runs first — setTimeout(0) or Promise.then? Intermediate

The event loop runs JavaScript on a single thread by processing a queue of tasks. After each macrotask (script, setTimeout, setInterval, I/O), the engine drains the entire microtask queue before picking the next macrotask. Promise callbacks (.then/.catch/.finally) and queueMicrotask are microtasks; setTimeout/setInterval callbacks are macrotasks.

Therefore Promise.then always runs before setTimeout(fn, 0) even if the promise resolves synchronously, because microtasks drain before the callback queue is checked.

setTimeout(() => console.log("A"), 0);   // macrotask
Promise.resolve().then(() => console.log("B")); // microtask
console.log("C"); // sync
// Output: C → B → A
What is the difference between Promises and async/await? When would you choose one over the other? Intermediate

async/await is syntactic sugar built on top of Promises — under the hood it creates and chains Promises. There is no runtime difference. async/await is preferred for its readability: sequential async steps look synchronous, and try/catch handles rejections naturally.

Raw Promise chains are better when you need to run operations concurrently with Promise.all, or when writing utilities that compose Promises. Avoid async functions inside .then() chains — it creates an implicit inner Promise you can accidentally forget to return.

// Concurrent with Promise.all (preferred over sequential await)
const [user, posts] = await Promise.all([fetchUser(id), fetchPosts(id)]);
How does the prototype chain work? What happens when you access a property? Intermediate

Every object has an internal [[Prototype]] slot (accessible via Object.getPrototypeOf()). When you access a property, the engine checks the object itself first; if not found, it follows the prototype link, then that object's prototype, continuing up the chain until it reaches null (Object.prototype's prototype). If still not found, the result is undefined.

With ES6 classes, extends sets up the prototype chain automatically: instance.__proto__ === ChildClass.prototype and ChildClass.prototype.__proto__ === ParentClass.prototype.

function Animal(name) { this.name = name; }
Animal.prototype.speak = function() { return `${this.name} makes a sound`; };
const dog = new Animal("Rex");
console.log(dog.hasOwnProperty("name"));  // true (own)
console.log(dog.hasOwnProperty("speak")); // false (on prototype)
What is the difference between debounce and throttle? Give a use case for each. Intermediate

Debounce delays execution until a burst of calls stops for a given period. The timer resets on every call. Best for: search input (fire API only after user stops typing), window resize recalculation, form validation on blur.

Throttle guarantees execution at most once per interval regardless of how many calls arrive. Best for: scroll handlers (update sticky nav at most 10×/sec), mousemove tracking, API rate limiting, button click guard.

Key mental model: debounce = "wait until quiet"; throttle = "fire at regular cadence, ignore the rest".

Advanced

Implement Promise.all from scratch. Advanced

Promise.all takes an iterable of promises, resolves with an array of results when all fulfill (in original order), and rejects immediately with the first rejection.

function promiseAll(promises) {
  return new Promise((resolve, reject) => {
    const results = [];
    let remaining = promises.length;
    if (remaining === 0) return resolve(results);
    promises.forEach((p, i) => {
      Promise.resolve(p).then(val => {
        results[i] = val;
        if (--remaining === 0) resolve(results);
      }, reject); // first rejection propagates immediately
    });
  });
}

Edge cases: empty array resolves synchronously to []; non-Promise values are wrapped with Promise.resolve(); results are stored at the original index so order is preserved even if promises settle out of order.

Explain microtask vs macrotask queues in depth. Name all sources of each. Advanced

Microtasks (drained after every task, before rendering):

  • Promise.then / .catch / .finally
  • queueMicrotask(fn)
  • MutationObserver callbacks
  • await continuations (desugars to .then)

Macrotasks / Tasks (one per event loop turn):

  • Script evaluation (initial load)
  • setTimeout / setInterval
  • setImmediate (Node.js)
  • I/O callbacks, MessageChannel, postMessage
  • UI events (click, keydown)

requestAnimationFrame is in neither — it runs before the next paint, after microtasks, as part of the render step. process.nextTick in Node.js runs before the microtask queue.

Write a generic curry function that supports both partial application and direct call. Advanced

Currying transforms a multi-argument function into a chain of single-argument functions. The key insight: if enough arguments have been collected (≥ arity), invoke the original; otherwise return a new curried function waiting for more.

function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn.apply(this, args);
    }
    return function(...more) {
      return curried.apply(this, args.concat(more));
    };
  };
}
const add = curry((a, b, c) => a + b + c);
add(1)(2)(3);   // 6
add(1, 2)(3);   // 6
add(1)(2, 3);   // 6
add(1, 2, 3);   // 6
How do you implement generator-based async flow control (like async/await)? Advanced

Before async/await, libraries (co.js, redux-saga) used generators: yield a Promise, receive the resolved value back. A runner drives the generator, calling .next(resolvedValue) on each fulfillment and .throw(error) on rejection.

function run(genFn) {
  return new Promise((resolve, reject) => {
    const gen = genFn();
    function step(val, isErr) {
      let result;
      try { result = isErr ? gen.throw(val) : gen.next(val); }
      catch (e) { return reject(e); }
      if (result.done) return resolve(result.value);
      Promise.resolve(result.value).then(v => step(v, false), e => step(e, true));
    }
    step();
  });
}
run(function* () {
  const data = yield fetch("/api/data").then(r => r.json());
  console.log(data);
});

Very Advanced

What are V8 hidden classes (shapes) and how do they affect performance? Very Advanced

V8 JIT-compiles JavaScript by assuming objects with the same "shape" (property names added in the same order) share a hidden class (also called a Map/Shape). This lets the engine generate fast native code that accesses properties at a fixed memory offset instead of doing a dictionary lookup.

When you change an object's shape (add/delete properties, add them in a different order), V8 creates a new hidden class and the property-access code becomes a slower "megamorphic" call site. Best practices:

  • Always initialise all properties in the constructor (same order).
  • Avoid delete obj.prop — set to undefined instead.
  • Don't add properties dynamically outside the constructor.
  • Keep property types consistent (monomorphic sites are fastest).
// GOOD — single hidden class
class Point { constructor(x, y) { this.x = x; this.y = y; } }

// BAD — two shapes, deoptimises call sites
const a = {}; a.x = 1; a.y = 2;
const b = {}; b.y = 1; b.x = 2; // different insertion order
Implement a basic Observable (RxJS-style) with subscribe, next, error, and complete. Very Advanced

An Observable is a lazy push-based data source. It does nothing until subscribed. The subscriber object receives next, error, and complete callbacks. The subscribe function returns a teardown/unsubscribe handle.

class Observable {
  constructor(subscribeFn) { this._subscribeFn = subscribeFn; }
  subscribe(observer) {
    const safe = {
      next:     v  => !safe._closed && observer.next?.(v),
      error:    e  => { if (!safe._closed) { safe._closed = true; observer.error?.(e); } },
      complete: () => { if (!safe._closed) { safe._closed = true; observer.complete?.(); } },
      _closed: false,
    };
    const teardown = this._subscribeFn(safe);
    return { unsubscribe: () => { safe._closed = true; teardown?.(); } };
  }
  static from(arr) {
    return new Observable(obs => {
      arr.forEach(v => obs.next(v)); obs.complete();
    });
  }
}

Implement a reactive state management system (like a mini-Vue/MobX signal). Very Advanced

Reactive state tracks which computations ("effects") read each piece of state. When state changes, dependent effects re-run automatically. The pattern uses a global "currently running effect" pointer to auto-subscribe during reads.

let activeEffect = null;
function signal(initial) {
  let value = initial;
  const subscribers = new Set();
  return {
    get() { if (activeEffect) subscribers.add(activeEffect); return value; },
    set(v) { value = v; subscribers.forEach(fn => fn()); },
  };
}
function effect(fn) {
  const run = () => { activeEffect = run; fn(); activeEffect = null; };
  run();
}
const count  = signal(0);
const double = signal(0);
effect(() => { double.set(count.get() * 2); });
count.set(5);
console.log(double.get()); // 10 — auto-derived

This is the foundation of Vue 3 Composition API signals, SolidJS, and TC39 Signals proposal. The key invariant: always clear activeEffect after running to avoid stale subscriptions.
