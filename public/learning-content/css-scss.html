1. CSS Box Model

Every element is a rectangular box. The box model layers (from inside out): content → padding → border → margin.

/* content-box (default): width applies to content only */
.default { box-sizing: content-box; width: 200px; padding: 20px; } /* total width: 240px */

/* border-box: width includes padding and border */
.modern { box-sizing: border-box; width: 200px; padding: 20px; } /* total width: 200px */

/* Apply border-box globally — best practice */
*, *::before, *::after { box-sizing: border-box; }
PropertyDescriptionExample
marginSpace outside border (can be negative)margin: 10px 20px
paddingSpace between content and borderpadding: 8px 16px
borderVisible line around elementborder: 1px solid #ccc
outlineLike border but doesn't affect layoutoutline: 2px solid blue

2. Selectors & Specificity

/* Type, Class, ID */
p { color: black; }          /* specificity: 0,0,1 */
.highlight { color: yellow; } /* specificity: 0,1,0 */
#header { color: red; }       /* specificity: 1,0,0 */

/* Attribute selectors */
input[type="email"] { border: 1px solid blue; }
a[href^="https"] { color: green; } /* starts with */
a[href$=".pdf"]  { color: red; }   /* ends with */

/* Pseudo-classes */
a:hover, a:focus { text-decoration: underline; }
li:nth-child(2n) { background: #f0f0f0; }  /* even rows */
p:first-of-type  { font-weight: bold; }

/* Pseudo-elements */
p::before { content: "→ "; }
p::after  { content: " ←"; }
::selection { background: #58a6ff; color: white; }

/* Combinators */
/* div p   — descendant: all p inside div */
/* div > p — child: direct p children of div */
/* h2 + p  — adjacent sibling: p immediately after h2 */
/* h2 ~ p  — general sibling: all p after h2 */

Specificity calculation: inline style = 1000, ID = 100, class/pseudo-class/attribute = 10, element/pseudo-element = 1. Higher wins; equal specificity → last rule wins. !important overrides all (use sparingly).

3. Flexbox

.container {
  display: flex;
  flex-direction: row;          /* row | column | row-reverse | column-reverse */
  flex-wrap: wrap;              /* nowrap | wrap | wrap-reverse */
  justify-content: space-between; /* main axis: flex-start|center|flex-end|space-between|space-around|space-evenly */
  align-items: center;          /* cross axis: stretch|flex-start|flex-end|center|baseline */
  align-content: flex-start;    /* multi-line cross axis */
  gap: 16px;                    /* shorthand for row-gap + column-gap */
}

.item {
  flex-grow: 1;    /* how much extra space to take (0 = none) */
  flex-shrink: 1;  /* how much to shrink if needed (0 = no shrink) */
  flex-basis: 200px; /* initial size before grow/shrink */
  flex: 1 1 200px;   /* shorthand */
  align-self: flex-end; /* override align-items for this item */
  order: 2;          /* visual ordering (default 0) */
}

/* Common patterns */
.center { display:flex; justify-content:center; align-items:center; }
.sidebar-layout { display:flex; gap:20px; }
.sidebar-layout aside { flex: 0 0 260px; }
.sidebar-layout main  { flex: 1; }

4. CSS Grid

.grid {
  display: grid;
  grid-template-columns: 260px 1fr 1fr;          /* explicit columns */
  grid-template-columns: repeat(3, 1fr);          /* 3 equal columns */
  grid-template-columns: repeat(auto-fill, minmax(200px, 1fr)); /* responsive */
  grid-template-rows: auto 1fr auto;
  grid-template-areas:
    "header header header"
    "sidebar main   main"
    "footer footer footer";
  gap: 16px;
}

.header  { grid-area: header; }
.sidebar { grid-area: sidebar; }
.main    { grid-area: main; }

/* Placement */
.item {
  grid-column: 1 / 3;   /* span columns 1 to 3 */
  grid-column: span 2;  /* span 2 columns */
  grid-row: 2 / 4;
}

5. Positioning

/* static — default, no top/left/right/bottom effect */
/* relative — offset from its normal position, still in flow */
.relative { position: relative; top: 10px; left: 20px; }

/* absolute — removed from flow, positioned relative to nearest non-static ancestor */
.parent   { position: relative; }
.absolute { position: absolute; top: 0; right: 0; }

/* fixed — relative to viewport, stays while scrolling */
.navbar { position: fixed; top: 0; left: 0; right: 0; z-index: 100; }

/* sticky — relative until scroll threshold, then fixed */
.sticky-header { position: sticky; top: 0; z-index: 10; }

7. Responsive Design

/* Mobile-first approach — start with small, add complexity */
.container { padding: 16px; }

@media (min-width: 768px) {
  .container { padding: 24px; max-width: 960px; margin: 0 auto; }
}
@media (min-width: 1200px) {
  .container { max-width: 1280px; }
}

/* Fluid typography with clamp(min, preferred, max) */
h1 { font-size: clamp(1.5rem, 4vw, 3rem); }
.gap { gap: clamp(8px, 2vw, 24px); }

/* Container queries (modern — target element size, not viewport) */
@container sidebar (min-width: 400px) {
  .card { display: flex; }
}
.sidebar { container-type: inline-size; container-name: sidebar; }

/* Breakpoints reference */
/* 320px — small phones, 480px — phones, 768px — tablets, 1024px — laptops, 1280px — desktops */

8. Transitions & Animations

/* Transition — smooth state changes */
.button {
  background: #58a6ff;
  transition: background 0.2s ease, transform 0.15s ease;
}
.button:hover { background: #79c0ff; transform: translateY(-2px); }

/* Keyframe animation */
@keyframes fadeIn {
  from { opacity: 0; transform: translateY(8px); }
  to   { opacity: 1; transform: translateY(0); }
}

.modal {
  animation: fadeIn 0.3s ease forwards;
  /* animation: name duration timing-function delay iteration-count direction fill-mode */
}

/* Performance: prefer transform and opacity (compositor layer) */
/* Avoid: animating width, height, top, left (triggers layout) */

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation-duration: 0.01ms !important; }
}

9. Modern CSS Features

/* aspect-ratio */
.video-embed { width: 100%; aspect-ratio: 16 / 9; }

/* Logical properties (writing-mode aware) */
.box { margin-inline: auto; padding-block: 16px; }
/* instead of: margin-left: auto; margin-right: auto; padding-top: 16px; */

/* :is() — reduce repetition */
:is(h1, h2, h3) { line-height: 1.3; }
:is(article, section) :is(h2, h3) { color: #79c0ff; }

/* :where() — same as :is() but zero specificity */
:where(.card, .panel) { border-radius: 6px; }

/* :has() — parent selector! */
.form-group:has(input:invalid) { border-color: red; }
nav:has(.active) { background: #161b22; }

/* @layer — explicit cascade layers */
@layer base, components, utilities;
@layer base { p { margin-bottom: 1em; } }
@layer utilities { .mt-4 { margin-top: 1rem; } }

/* color-mix() */
.button { background: color-mix(in srgb, #58a6ff 80%, white); }

/* CSS nesting (native, no preprocessor needed) */
.card {
  padding: 16px;
  &:hover { box-shadow: 0 4px 12px rgba(0,0,0,.3); }
  & .title { font-size: 1.2rem; }
}

10. CSS Architecture

BEM (Block__Element--Modifier)

/* Block */         .card { ... }
/* Element */       .card__title { ... }  .card__body { ... }
/* Modifier */      .card--featured { ... }  .card__title--large { ... }

Utility-First (Tailwind style)

<div class="flex gap-4 p-6 rounded-lg bg-gray-900">
  <h2 class="text-xl font-bold text-white">Title</h2>
</div>

CSS Modules — scopes class names to the component automatically. .card becomes .card_a1b2c3 in the output, preventing collisions.

11. SCSS / Sass

// Variables
$color-primary: #58a6ff;
$spacing-md: 16px;

// Nesting and & parent selector
.nav {
  display: flex;
  gap: $spacing-md;

  &__item { color: #c9d1d9; }       // .nav__item
  &__item:hover { color: $color-primary; }
  &--dark { background: #0d1117; }  // .nav--dark
}

// Mixin with arguments
@mixin flex-center($direction: row) {
  display: flex;
  flex-direction: $direction;
  justify-content: center;
  align-items: center;
}
.hero { @include flex-center(column); }

// Function
@function rem($px) {
  @return #{$px / 16}rem;
}
h1 { font-size: rem(32); } // 2rem

// @extend
%button-base {
  padding: 8px 16px;
  border-radius: 6px;
  cursor: pointer;
}
.btn-primary { @extend %button-base; background: $color-primary; }
.btn-danger   { @extend %button-base; background: #ff7b72; }

// Control flow
@each $color in primary, danger, success {
  .btn-#{$color} { color: var(--color-#{$color}); }
}

@for $i from 1 through 5 {
  .mt-#{$i} { margin-top: #{$i * 4}px; }
}

// Partials and @use (@use replaces old @import)
// _variables.scss, _mixins.scss, _components.scss
@use 'variables' as v;
@use 'mixins';
.box { color: v.$color-primary; }

// Maps
$breakpoints: (sm: 576px, md: 768px, lg: 1024px, xl: 1280px);
@each $key, $val in $breakpoints {
  .container-#{$key} { max-width: $val; }
}

13. Interview Q&A

What is the CSS box model? Easy

Every element is a rectangular box with four layers: content (text/images), padding (space between content and border), border (visible line), and margin (space outside border, transparent). The key property is box-sizing: default content-box adds padding/border on top of the declared width, while border-box includes them in the width — making layout math much easier. Best practice is *, *::before, *::after { box-sizing: border-box; } globally.

Explain CSS specificity. Easy

Specificity determines which rule wins when multiple rules target the same element. Points: inline style = 1000, ID = 100, class/pseudo-class/attribute = 10, element/pseudo-element = 1. Example: #nav .link:hover = 100+10+10 = 120. Equal specificity → last rule in source wins. !important overrides all (avoid unless necessary). The universal selector * and combinators (>, +, ~) have zero specificity. :where() is like :is() but adds 0 specificity.

Flexbox vs CSS Grid — when to use each? Easy

Flexbox is 1D: align items along one axis (row or column). Use it for navigation bars, button groups, centering a single item, or any component where items flow in a line. CSS Grid is 2D: place items in rows and columns simultaneously. Use it for page layouts, card grids, or any component needing precise placement in both dimensions. They compose well: use Grid for the page skeleton, Flexbox within each grid cell.

What is the difference between visibility: hidden and display: none? Easy

display: none removes the element from the layout entirely — it takes up no space and is not accessible to screen readers. visibility: hidden hides the element visually but it still occupies its space in the layout. opacity: 0 also hides visually while taking space, but still receives pointer events (unlike visibility:hidden). For accessibility-friendly hiding, clip-path: inset(50%) or the visually-hidden pattern (position:absolute; clip) hides visually but remains accessible to screen readers.

How does the CSS cascade work? Intermediate

The cascade resolves conflicts using this priority order (highest first): 1) !important user agent styles, 2) !important author styles, 3) !important user styles, 4) author styles (normal), 5) user styles, 6) user-agent defaults. Within author styles: @layer order (later layers win), then specificity, then source order. CSS @layer lets you explicitly control cascade order regardless of specificity, which is powerful for third-party CSS overrides.

Explain CSS stacking context and z-index. Intermediate

A stacking context is a 3D layer in which elements are painted in z-order. Elements with higher z-index appear in front, but only within the same stacking context. A new context is created by: position+z-index not auto, opacity < 1, transform/filter/will-change, isolation: isolate, and more. Common bug: z-index:9999 on a child does nothing if a parent has z-index:1 in a separate stacking context — the parent's context is compared, not the child's. Use isolation: isolate to create a context without affecting layout.

What are CSS custom properties and how do they differ from SCSS variables? Intermediate

CSS custom properties (declared as --name: value) are native browser features that exist at runtime and can be changed with JavaScript or inherit through the DOM. They can be updated per-component or per-theme dynamically. SCSS variables ($name: value) are compile-time — they are resolved at build time and compiled away; the final CSS has no variable references. CSS custom properties also participate in the cascade and inheritance, while SCSS variables are static. For theming and dynamic values: CSS custom properties. For SCSS-only computed values and loops: SCSS variables.

What is BEM and why use it? Intermediate

BEM (Block__Element--Modifier) is a CSS naming convention to avoid style conflicts in large codebases. Block = standalone component (.card), Element = part of a block (.card__title, .card__body), Modifier = variation (.card--featured, .card__title--large). Benefits: class names are self-documenting, specificity stays at 0,1,0 (one class), no nesting needed to avoid conflicts. Downsides: verbose class names. Alternatives include CSS Modules (automated scoping), utility-first (Tailwind), or CSS-in-JS.

How do CSS container queries differ from media queries? Advanced

Media queries respond to the viewport size; container queries respond to the size of a parent element. This enables truly reusable components that adapt to their context regardless of where they're placed. You mark a parent as a container (container-type: inline-size) and then write @container (min-width: 400px) { ... }. This solves the classic problem of a card component that needs to be wide in a full-width layout but compact in a sidebar — without CSS knowing the viewport, only knowing its container's size. Browser support is now excellent (Chrome 105+, Safari 16+, Firefox 110+).

Explain the :has() selector and its use cases. Advanced

:has() is a relational pseudo-class that selects an element if it contains a matching descendant — effectively a "parent selector" long missing from CSS. Examples: .form-group:has(input:invalid) (style form group red when input is invalid), article:has(img) (different layout for articles with images), li:has(+ li) (all li except the last), header:has(nav) (header that contains nav). It has the specificity of its argument. Combined with :not(:has(...)) enables powerful conditional styling without JavaScript class manipulation.

What is CSS @layer and when would you use it? Advanced

CSS @layer lets you explicitly define the order of the cascade, independent of specificity. You declare layer order: @layer base, components, utilities; — later layers win, so utilities override components override base. This solves the specificity wars in large codebases: a utility class with specificity 0,1,0 beats a component class with 0,1,0 if it's in a higher layer, without needing !important. Primary use case: when importing third-party CSS (Bootstrap, Normalize) you can wrap it in a lower layer: @layer vendor { @import "bootstrap.css"; } so your styles always win regardless of specificity.

Explain SCSS @use vs @import and the module system. Advanced

@import (deprecated) makes everything global and executes the file every time — causing duplicate CSS in output and namespace collisions. @use loads a file once (deduped), creates a namespace (@use 'variables' as v; → v.$color-primary), and keeps private members (prefixed with _ or -) private. @forward re-exports a module's public API for consumers. The module system enables better encapsulation, avoids global leakage, and the compiler can tree-shake unused mixins/functions. Migrate: replace all @import with @use/@forward, and update variable references to use namespaces.

How do you implement a performant CSS animation? What should you avoid? Advanced

For performant animations, only animate properties that the compositor can handle without involving the main thread: transform (translate, scale, rotate) and opacity. These avoid layout (reflow) and paint, running entirely on the GPU. Add will-change: transform to hint the browser to promote the element to its own compositor layer (use sparingly — it consumes GPU memory). Avoid animating width, height, top, left, padding, margin — these trigger layout, which is expensive. Use @keyframes + CSS animations over JS setInterval; use requestAnimationFrame if JS is needed. Always add @media (prefers-reduced-motion: reduce) to disable animations for users who prefer less motion.

Explain the critical rendering path and how CSS affects it. Very Advanced

The critical rendering path: 1) Parse HTML → DOM tree, 2) Parse CSS → CSSOM tree, 3) Combine DOM+CSSOM → Render Tree (only visible elements), 4) Layout (calculate positions/sizes), 5) Paint (fill pixels), 6) Composite (combine layers). CSS blocks rendering: the browser won't render until all CSS is parsed (CSS is render-blocking). Optimization strategies: inline critical CSS (above-the-fold styles) in <style>, load non-critical CSS asynchronously (<link rel="preload" as="style" onload="this.rel='stylesheet'">), minimize selector complexity (right-to-left matching), avoid @import in CSS (creates serial waterfalls). Forced reflows happen when JS reads layout properties (offsetWidth, getBoundingClientRect) after DOM mutations — batch reads/writes or use requestAnimationFrame.

Implement a CSS-only responsive masonry layout and explain its limitations. Very Advanced

CSS-only masonry: using column-count (multi-column layout) achieves a masonry-like effect: .masonry { column-count: 3; column-gap: 16px; } .masonry-item { break-inside: avoid; }. Items fill columns top-to-bottom, left-to-right. Limitation: DOM order follows columns (1→4→7, 2→5→8), which breaks visual reading order and accessibility. The CSS Grid masonry spec (grid-template-rows: masonry) solves this — items follow row order (1→2→3) but fill the shortest column — but it's still experimental (2024). A JS solution (Masonry.js, CSS Grid with JS height measurement) maintains DOM order while achieving masonry visually. Container queries make the column-count responsive without JS.
