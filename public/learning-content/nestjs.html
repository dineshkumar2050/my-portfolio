NestJS — Comprehensive Learning Reference

Architecture Overview

NestJS is a progressive Node.js framework built on top of Express (or Fastify) that brings Angular-inspired architecture to backend development. It uses TypeScript decorators to declare the structure of your application.

Building BlockPurposeDecorator
ModuleOrganises related code into cohesive units@Module()
ControllerHandles incoming HTTP requests, returns responses@Controller()
Provider / ServiceBusiness logic, injectable dependencies@Injectable()
MiddlewareRuns before route handler (like Express middleware)implements NestMiddleware
GuardDetermines if a request should be handled (AuthN/AuthZ)@UseGuards()
InterceptorTransform/log/cache before & after route handler@UseInterceptors()
PipeTransform and validate input data@UsePipes()
Exception FilterCatch and format thrown exceptions@UseFilters()

Request Lifecycle

graph TD A[Incoming Request] --> B[Middleware\nnext called] B --> C[Guards\ncanActivate] C -->|true| D[Interceptors\nbefore handle] C -->|false| Z[403 Forbidden] D --> E[Pipes\ntransform + validate] E --> F[Route Handler\nController method] F --> G[Interceptors\nafter handle - map response] G --> H[Exception Filters\nif error thrown] H --> I[Response sent] style C fill:#1a4731,color:#3fb950 style E fill:#1f3358,color:#58a6ff style D fill:#2d2b00,color:#e3b341 style H fill:#3d1f00,color:#f0883e style Z fill:#3d0000,color:#ff7b72

Order: Middleware → Guards → Interceptors (pre) → Pipes → Route Handler → Interceptors (post) → Exception Filters

Dependency Injection System

NestJS's DI system is based on inversion of control (IoC). Providers are registered in a module and injected via constructor parameters. The DI container resolves the dependency graph at bootstrap.

@Injectable()
export class UsersService {
  constructor(
    @InjectRepository(User)
    private readonly userRepository: Repository<User>,
    private readonly configService: ConfigService,
    private readonly mailService: MailService,
  ) {}
}

@Module({
  providers: [UsersService, MailService],
  exports: [UsersService],  // export to be used by other modules
})
export class UsersModule {}

// Custom guard — roles-based
@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const requiredRoles = this.reflector.getAllAndOverride<Role[]>('roles', [
      context.getHandler(),  // method-level metadata
      context.getClass(),    // class-level metadata
    ]);
    if (!requiredRoles) return true;  // no roles required — allow

    const { user } = context.switchToHttp().getRequest();
    return requiredRoles.some(role => user.roles.includes(role));
  }
}

// Apply guards

Interceptors

// Transform response — wrap all responses in { data: ... }
@Injectable()
export class TransformInterceptor<T> implements NestInterceptor<T, ApiResponse<T>> {
  intercept(context: ExecutionContext, next: CallHandler): Observable<ApiResponse<T>> {
    return next.handle().pipe(
      map(data => ({ success: true, data, timestamp: new Date().toISOString() }))
    );
  }
}

// Logging interceptor
@Injectable()
export class LoggingInterceptor implements NestInterceptor {
  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
    const req = context.switchToHttp().getRequest();
    const start = Date.now();
    return next.handle().pipe(
      tap(() => console.log(`${req.method} ${req.url} - ${Date.now() - start}ms`)),
      catchError(err => {
        console.error(`${req.method} ${req.url} - ERROR: ${err.message}`);
        return throwError(() => err);
      })
    );
  }
}

// Timeout interceptor
@Injectable()
export class TimeoutInterceptor implements NestInterceptor {
  intercept(_: ExecutionContext, next: CallHandler): Observable<any> {
    return next.handle().pipe(timeout(5000));
  }
}

// Cache interceptor
@Injectable()
export class CacheInterceptor implements NestInterceptor {
  constructor(private cache: CacheService) {}

  async intercept(ctx: ExecutionContext, next: CallHandler): Promise<Observable<any>> {
    const key = ctx.switchToHttp().getRequest().url;
    const cached = await this.cache.get(key);
    if (cached) return of(cached);
    return next.handle().pipe(
      tap(data => this.cache.set(key, data, 60))
    );
  }
}

// Global interceptor via DI
providers: [{ provide: APP_INTERCEPTOR, useClass: TransformInterceptor }]

// DTO with class-validator
import { IsEmail, IsString, MinLength, IsOptional, IsInt, Min, Max } from 'class-validator';
import { Transform, Type } from 'class-transformer';

export class CreateUserDto {
  @IsString()
  @MinLength(2)
  name: string;

  @IsEmail()
  @Transform(({ value }) => value.toLowerCase().trim())
  email: string;

  @IsOptional()
  @IsInt()
  @Min(0)
  @Max(120)
  @Type(() => Number)  // auto-cast string to number from query params
  age?: number;
}

// Custom pipe
@Injectable()
export class TrimPipe implements PipeTransform {
  transform(value: any) {
    if (typeof value === 'string') return value.trim();
    if (typeof value === 'object' && value !== null) {
      return Object.fromEntries(
        Object.entries(value).map(([k, v]) => [k, typeof v === 'string' ? v.trim() : v])
      );
    }
    return value;
  }
}

// Custom exception filter
@Catch()  // catch all
export class GlobalExceptionFilter implements ExceptionFilter {
  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse<Response>();
    const request = ctx.getRequest<Request>();

    let status = HttpStatus.INTERNAL_SERVER_ERROR;
    let message = 'Internal server error';

    if (exception instanceof HttpException) {
      status = exception.getStatus();
      const res = exception.getResponse();
      message = typeof res === 'object' ? (res as any).message : res;
    } else if (exception instanceof Error) {
      message = exception.message;
    }

    response.status(status).json({
      statusCode: status,
      message,
      path: request.url,
      timestamp: new Date().toISOString(),
    });
  }
}

// Entity
@Entity('users')
export class User {
  @PrimaryGeneratedColumn('uuid')
  id: string;

  @Column({ unique: true })
  email: string;

  @Column()
  @Exclude()  // class-transformer — exclude from responses
  password: string;

  @Column({ default: true })
  isActive: boolean;

  @CreateDateColumn()
  createdAt: Date;

  @UpdateDateColumn()
  updatedAt: Date;

  @OneToMany(() => Post, post => post.author, { cascade: true })
  posts: Post[];
}

@Entity('posts')
export class Post {
  @PrimaryGeneratedColumn('uuid')
  id: string;

  @Column()
  title: string;

  @ManyToOne(() => User, user => user.posts, { onDelete: 'CASCADE' })
  @JoinColumn({ name: 'author_id' })
  author: User;

  @Column({ name: 'author_id' })
  authorId: string;
}

// Repository pattern in service
@Injectable()
export class UsersService {
  constructor(
    @InjectRepository(User)
    private repo: Repository<User>,
    private dataSource: DataSource,
  ) {}

  async findAll(query: PaginationDto) {
    return this.repo.findAndCount({
      where: { isActive: true },
      relations: ['posts'],
      order: { createdAt: 'DESC' },
      take: query.limit,
      skip: query.offset,
    });
  }

  async findWithQueryBuilder(search: string) {
    return this.repo.createQueryBuilder('user')
      .leftJoinAndSelect('user.posts', 'post')
      .where('user.email ILIKE :search OR user.name ILIKE :search', { search: `%${search}%` })
      .andWhere('user.isActive = :active', { active: true })
      .orderBy('user.createdAt', 'DESC')
      .take(20)
      .getMany();
  }

  // Transactions
  async transferCredits(fromId: string, toId: string, amount: number) {
    return this.dataSource.transaction(async manager => {
      const from = await manager.findOneOrFail(User, { where: { id: fromId }, lock: { mode: 'pessimistic_write' } });
      const to = await manager.findOneOrFail(User, { where: { id: toId } });
      from.credits -= amount;
      to.credits += amount;
      await manager.save([from, to]);
    });
  }
}

JWT Authentication

// Install: @nestjs/passport @nestjs/jwt passport passport-jwt passport-local

// JWT Strategy
@Injectable()
export class JwtStrategy extends PassportStrategy(Strategy, 'jwt') {
  constructor(configService: ConfigService) {
    super({
      jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken(),
      secretOrKey: configService.getOrThrow('JWT_SECRET'),
      ignoreExpiration: false,
    });
  }

  async validate(payload: JwtPayload): Promise<User> {
    // payload is the decoded JWT — return value becomes req.user
    return { id: payload.sub, email: payload.email, roles: payload.roles };
  }
}

// Local Strategy (username/password)
@Injectable()
export class LocalStrategy extends PassportStrategy(Strategy, 'local') {
  constructor(private authService: AuthService) {
    super({ usernameField: 'email' });
  }

  async validate(email: string, password: string): Promise<User> {
    const user = await this.authService.validateUser(email, password);
    if (!user) throw new UnauthorizedException('Invalid credentials');
    return user;
  }
}

// AuthService
@Injectable()
export class AuthService {
  constructor(
    private usersService: UsersService,
    private jwtService: JwtService,
  ) {}

  async login(user: User) {
    const payload: JwtPayload = { sub: user.id, email: user.email, roles: user.roles };
    return {
      accessToken: this.jwtService.sign(payload, { expiresIn: '15m' }),
      refreshToken: this.jwtService.sign({ sub: user.id }, {
        secret: process.env.JWT_REFRESH_SECRET,
        expiresIn: '7d',
      }),
    };
  }

  async refresh(refreshToken: string) {
    const payload = this.jwtService.verify(refreshToken, { secret: process.env.JWT_REFRESH_SECRET });
    const user = await this.usersService.findById(payload.sub);
    return this.login(user);
  }
}

WebSockets

import { WebSocketGateway, WebSocketServer, SubscribeMessage,
         MessageBody, ConnectedSocket, OnGatewayConnection, OnGatewayDisconnect } from '@nestjs/websockets';
import { Server, Socket } from 'socket.io';

@WebSocketGateway(3001, {
  cors: { origin: '*' },
  namespace: '/chat',
})
export class ChatGateway implements OnGatewayConnection, OnGatewayDisconnect {
  @WebSocketServer()
  server: Server;

  async handleConnection(client: Socket) {
    const user = await this.authService.validateSocket(client);
    if (!user) return client.disconnect();
    client.data.user = user;
    client.join(`room:${user.roomId}`);
  }

  handleDisconnect(client: Socket) {
    console.log(`Client disconnected: ${client.id}`);
  }

  @SubscribeMessage('message')
  handleMessage(
    @MessageBody() data: { content: string; roomId: string },
    @ConnectedSocket() client: Socket,
  ) {
    const message = { ...data, sender: client.data.user, timestamp: Date.now() };
    // Emit to all in room except sender
    client.to(`room:${data.roomId}`).emit('message', message);
    return message;  // ACK back to sender
  }

  // Broadcast from service
  broadcastToRoom(roomId: string, event: string, data: any) {
    this.server.to(`room:${roomId}`).emit(event, data);
  }
}

Interview Q&A

Q1: What is NestJS and what problems does it solve? Easy

NestJS is a Node.js framework for building scalable server-side applications. It addresses the lack of structure in Express/Fastify apps by providing:

  • Architecture: Modules, Controllers, Providers — enforced separation of concerns
  • Dependency Injection: IoC container manages dependencies and their lifecycle
  • TypeScript-first: Full TypeScript support with decorators
  • Testability: DI makes mocking trivial; built-in testing utilities
  • Ecosystem: Official packages for every concern (auth, DB, queues, GraphQL, microservices)

It is inspired by Angular's architecture and brings similar patterns to the backend.

Q2: Explain the full NestJS request lifecycle. Easy

Incoming request → Middleware (express-style, next()) → Guards (canActivate — AuthN/AuthZ) → Interceptors (before handler — transform/log) → Pipes (validate/transform request data) → Route Handler → Interceptors (after handler — transform response) → Exception Filters (if anything threw).

Each layer can short-circuit: a Guard returning false stops the request (403), a Pipe throwing stops with 422/400, an Exception Filter catches anything thrown at any stage.

Q3: What are the different provider types in NestJS? Easy
  • useClass: Standard — provide a class instance (default)
  • useValue: Provide a static value (config, mocks, constants)
  • useFactory: Dynamic — factory function (supports async, receives injected deps via inject array)
  • useExisting: Alias — make an existing provider accessible under a different token
Q4: What is the difference between a Guard and Middleware for authentication? Intermediate

Middleware runs before routing — it doesn't know which route handler will be called. It cannot access the route metadata (decorators). Good for: logging, CORS, compression, cookie parsing.

Guard runs after routing (Nest knows the target handler). It receives the ExecutionContext — can read route metadata via Reflector (@Roles, @Public decorators). Can return false or throw to block the request. Much more powerful for authentication and authorization.

Use middleware for pre-routing concerns. Use guards for route-aware security.

Q5: How does the Reflector work with Guards and decorators? Intermediate 
// Set metadata on a route
export const Roles = (...roles: Role[]) => SetMetadata('roles', roles);

// Read metadata in a Guard
@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    // getAllAndOverride: handler-level overrides class-level
    const roles = this.reflector.getAllAndOverride<Role[]>('roles', [
      context.getHandler(),
      context.getClass(),
    ]);
    if (!roles) return true;
    return this.reflector.get('roles', context.getHandler())
      ?.some(r => req.user.roles.includes(r));
  }
}

getAllAndMerge merges arrays from both levels. getAllAndOverride uses the first non-null value (handler first).

Q6: What is the difference between @Res() and @Res({ passthrough: true })? Intermediate

Without passthrough: true, using @Res() puts the controller in "library-specific mode" — Nest stops managing the response lifecycle. You must call res.send() or res.end() yourself. Interceptors that wrap the response no longer work.

With { passthrough: true }, you can manipulate the response object (set headers, cookies) but still return from the handler normally. Nest sends the return value and interceptors work correctly.

@Post('login')
async login(@Body() dto: LoginDto, @Res({ passthrough: true }) res: Response) {
  const tokens = await this.authService.login(dto);
  res.cookie('refresh_token', tokens.refreshToken, { httpOnly: true, secure: true });
  return { accessToken: tokens.accessToken };  // Nest sends this
}
Q7: How do you implement request-scoped providers? Advanced

By default, providers are singletons (shared across the app). You can change scope:

@Injectable({ scope: Scope.REQUEST })
export class RequestContextService {
  // A new instance is created for EACH request
  // Can inject REQUEST to access the current request
  constructor(@Inject(REQUEST) private request: Request) {}
}

// Scopes:
// Scope.DEFAULT — singleton (shared)
// Scope.REQUEST — new instance per request (injecting this into a singleton is a problem — scope bubbles up!)
// Scope.TRANSIENT — new instance every time it's injected

Warning: If a singleton injects a REQUEST-scoped provider, the singleton also becomes REQUEST-scoped (scope bubbles). Use Scope.REQUEST sparingly — it adds overhead. For storing per-request context, prefer the AsyncLocalStorage pattern (zero-overhead, no scope bubbling).

Q8: How do Dynamic Modules work and when would you create one? Advanced

Dynamic Modules allow a module to be configured differently at import time — returning a DynamicModule with providers based on the passed options.

@Module({})
export class MailModule {
  static forRoot(config: MailConfig): DynamicModule {
    return {
      module: MailModule,
      providers: [
        { provide: MAIL_CONFIG, useValue: config },
        MailService,
      ],
      exports: [MailService],
    };
  }
}

// Usage
MailModule.forRoot({ host: 'smtp.gmail.com', port: 587 })

Use for: database connections, mailers, external API clients — anything that needs different configuration per environment or per feature module (forFeature pattern).

Q9: What is the difference between send and emit in microservices? Intermediate

send(pattern, data): Request-response. Returns an Observable. The client waits for a response from the microservice. The microservice handler must return a value. Use for queries that need a result.

emit(pattern, data): Fire-and-forget event. Returns void (Observable that completes immediately). The microservice handles it asynchronously. Use for events where the caller doesn't need a result (order placed, email notification triggered).

Corresponding microservice decorators: @MessagePattern handles send; @EventPattern handles emit.

Q10: How does ValidationPipe with whitelist: true protect against mass assignment? Intermediate

Mass assignment vulnerabilities occur when an attacker sends unexpected fields in the request body that get saved to the database (e.g., isAdmin: true).

whitelist: true strips any properties from the request body that are NOT declared with @ApiProperty or class-validator decorators in the DTO. These properties never reach the handler.

forbidNonWhitelisted: true takes it further — instead of silently stripping, it throws a BadRequestException listing the unexpected fields.

Combined with transform: true, the body is also automatically cast to the DTO class instance, enabling type coercion.

Q11: How do you implement caching with interceptors vs @nestjs/cache-manager? Advanced

Manual interceptor approach (full control): Inject a cache store, check for cached value in intercept() before calling next.handle(), store result on the way out. Can cache with custom keys, TTLs, and conditional logic.

@nestjs/cache-manager approach: Uses the CacheInterceptor + @CacheKey() / @CacheTTL() decorators. Register globally or per-route. Backed by cache-manager which supports Redis, Memcached, memory store. Less flexible but zero-boilerplate for simple GET caching.

CacheModule.registerAsync({
  useFactory: (config: ConfigService) => ({
    store: redisStore,
    host: config.get('REDIS_HOST'),
    ttl: 300,
  }),
  inject: [ConfigService],
})
Q12: How do you handle circular dependencies between modules? Advanced

Circular dependencies (Module A imports Module B, B imports A) cause DI resolution failures.

Solutions:

  1. Forward reference: forwardRef(() => ModuleB) in imports/providers — tells Nest to resolve lazily
  2. Restructure: Extract shared logic into a third module (SharedModule) that both import
  3. Events: Use EventEmitter or a message bus to decouple (Module A emits, Module B listens)
@Module({ imports: [forwardRef(() => UsersModule)] })
export class AuthModule {}

@Injectable()
export class AuthService {
  constructor(
    @Inject(forwardRef(() => UsersService))
    private usersService: UsersService,
  ) {}
}

Prefer restructuring. forwardRef is a code smell — circular deps usually mean poor separation of concerns.

Q13: What is the ExecutionContext and how is it used? Intermediate

ExecutionContext is an abstraction over the current request, available in Guards, Interceptors, and Exception Filters. It allows the same code to work across HTTP, WebSockets, microservices, and GraphQL.

// HTTP
const req = ctx.switchToHttp().getRequest<Request>();
const res = ctx.switchToHttp().getResponse<Response>();

// WebSocket
const client = ctx.switchToWs().getClient<Socket>();
const data = ctx.switchToWs().getData();

// Microservice
const rpcCtx = ctx.switchToRpc().getContext();

// GraphQL
const gqlCtx = GqlExecutionContext.create(ctx);
const info = gqlCtx.getInfo<GraphQLResolveInfo>();
const gqlReq = gqlCtx.getContext().req;
Q14: How does NestJS SWC support improve build times? Intermediate

SWC (Speedy Web Compiler) is a Rust-based JavaScript/TypeScript compiler, ~20x faster than the TypeScript compiler (tsc). NestJS 10 added first-class SWC support via @nestjs/cli:

nest start --builder swc  # dev server
nest build --builder swc  # build

Trade-off: SWC doesn't run TypeScript type checking. Use it for fast iteration during development, and run tsc --noEmit separately for type-checking in CI. NestJS CLI automatically runs SWC for transpilation + tsc for type-checking in parallel when typeCheck: true in nest-cli.json.

Q15: Explain durable providers introduced in NestJS 9 Advanced

Normally, request-scoped providers create a new instance per request (high overhead for high-traffic routes). Durable providers solve this for providers that differ by tenant/context but not per request.

Durable providers create one instance per unique "sub-tree" identifier (e.g., tenant ID). All requests from the same tenant share one provider instance.

@Injectable({ scope: Scope.REQUEST, durable: true })
export class TenantService {
  constructor(@Inject(REQUEST) private req: Request) {}
}

// Context ID factory — defines the "sub-tree" key
ContextIdFactory.apply(new AggregateByTenantContextIdStrategy());

Useful for: multi-tenant apps where each tenant needs isolated DB connections but you don't want one instance per request.

Q16: How does code-first GraphQL schema generation work in NestJS? Intermediate

NestJS code-first GraphQL uses decorators (@ObjectType, @Field, @Resolver, @Query, @Mutation) on TypeScript classes. The @nestjs/graphql package uses the TypeScript reflection metadata (reflect-metadata) and the class definitions to auto-generate the schema.gql file at startup.

The generated schema file can be committed and used for contract testing. The autoSchemaFile: true option generates in-memory (dev), while a path generates a file (CI-friendly).

Schema-first (alternative): write the SDL schema manually, NestJS generates TypeScript interfaces from it using GraphQLModule.forRoot({ typePaths: [...] }). Better for teams with dedicated GraphQL designers, but more boilerplate.

Q18: What is the APP_GUARD / APP_INTERCEPTOR / APP_PIPE / APP_FILTER pattern? Intermediate

These are special DI tokens that register components globally but through the DI system (not app.useGlobalGuards()).

The difference: app.useGlobalGuards(new X()) creates the guard outside the DI container — it cannot inject other providers. Using { provide: APP_GUARD, useClass: X } registers it within the DI container — full injection support.

@Module({
  providers: [
    { provide: APP_GUARD, useClass: JwtAuthGuard },
    { provide: APP_GUARD, useClass: RolesGuard },  // multiple — applied in order
    { provide: APP_INTERCEPTOR, useClass: TransformInterceptor },
    { provide: APP_PIPE, useClass: ValidationPipe },
    { provide: APP_FILTER, useClass: GlobalExceptionFilter },
  ],
})
export class AppModule {}

Q20: How do you implement database transactions across multiple services? Very Advanced

Options from simple to complex:

  1. Pass DataSource/EntityManager: Start transaction in a high-level service, pass the transaction manager to lower-level services as a parameter.
  2. Unit of Work with AsyncLocalStorage: Store the current transaction in AsyncLocalStorage. Lower-level services read it automatically without needing a parameter.
  3. Saga pattern (microservices): For distributed transactions across services, implement a saga orchestrator or choreography with compensating transactions (event-driven rollback).
// AsyncLocalStorage transaction context
@Injectable()
export class TransactionManager {
  private storage = new AsyncLocalStorage<EntityManager>();

  async run<T>(fn: (manager: EntityManager) => Promise<T>): Promise<T> {
    return this.dataSource.transaction(manager =>
      this.storage.run(manager, () => fn(manager))
    );
  }

  get current(): EntityManager {
    return this.storage.getStore() ?? this.dataSource.manager;
  }
}

// In services — automatically picks up transaction context
@Injectable()
export class UsersService {
  constructor(private tx: TransactionManager) {}
  async create(dto: CreateUserDto) {
    return this.tx.current.save(User, dto);  // uses active transaction if any
  }
}
